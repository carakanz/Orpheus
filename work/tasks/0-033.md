## Шаги

1. Отчёт сервера «запас прихода кадров» в снимке; L на клиенте по формуле и подстройке; номер кадра = оценка + L; L — в пакете ввода (2.7, 385 стр. «Пакет ввода»).
2. Сервер: опоздавший кадр не выбрасывается — нажатия кнопок переносятся в ближайший применяемый кадр («липкие»); граница ускорения 0-019 (≤ 2T + запас) держится.
3. Решение удара в кадре s + max(d, D_p + min(d; 0,3 с)); показ замаха у клиента не короче min(d; 0,3 с); значок высокой задержки.
4. Бот `dodge` — с честной нижней границей показа 0,3 с (как проверка 0-029).
5. Повтор шипа: имитатор RTT 100/200/250/300/300 пачками и 400/600 (2.7: опоздавших 0,01 % до 600 мс) по 100 замахов на 4 зёрнах; UDP 300. Критерий: при 300 мс ≥ 95 из 100, при 100–250 — не хуже 0-029.
6. Тесты: L = 0 при RTT ≤ 150 с обычным разбросом; L растёт с RTT; «липкое» нажатие в опоздавшем кадре засчитано; D_p ≤ 500 мс; мутации — без L, без «липких», без D_p.
