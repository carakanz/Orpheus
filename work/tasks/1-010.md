# 1-010 — копание инструментами по таблице разрушаемости, добыча в сумку

**Поток:** М (правила `01`, `05`, `06` в ядре). **Ветка:** `task/1-010` (рабочая копия `.claude/worktrees/t1010`). **Веха:** 1 «Прототип» (`08` 3.1, недели 16–17).

**Зависимости:** после слияния **1-002** (сумка, предмет в руках). **Параллельно можно:** 1-001, 1-003, 1-004, 1-007, 1-014, генератор, все К. **С 1-011 — общие `EditRules`, `NetServer.Edits.cs`, `NetClient.Edits.cs`: делать по очереди или сливать вторую влитием `main`.** **Ждут эту карточку:** 1-011 (желательно — ресурсы для постройки), 1-026.

**Цель:** дерево рубится топором, скала и залежь — киркой, у каждого объекта своё время по формуле Автора «база × модификатор», добыча падает в сумку в том же такте, что и правка тайла. Это половина цикла «копай — строй».

## Шаги

1. **Таблица объектов** (данными, рядом с `DigTimes`): требуемый инструмент (кирка / топор / руки) и ярус для объектов вехи 1 — дерево (топор 1), куст / трава (топор 1 или руки), валун и скала (кирка 1), гранит (кирка 2), залежь меди (кирка 1), пень; что даёт (дерево — 3 древесины, скала — 1–2 камня детерминированно по зерну и тайлу, залежь меди — 2–3 руды, куст — волокно). Объекты генератора 1-017 добавятся строками.
2. **Время** = база × модификатор объекта × множитель яруса (ярус выше нужного — ×0,5, `01` 5) — числа см. вопрос Автору; модификатор 0 — «нельзя».
3. **Отказы:** не тот инструмент — «нужен топор» / «нужна кирка»; ярус ниже — «нужна кирка: медная» (`01` приёмка 5 п. 3). Строки — к тем, что есть (0-028).
4. **Добыча атомарно** с правкой тайла в такте; два клиента копают один тайл — ресурс получает ровно один (тот, чью правку сервер принял первой), второй — «пусто». Клиент предсказывает счётчик и откатывает его вместе с тайлом.
5. **Снос постройки киркой** (`05` 1.3: 2 с) — через ту же таблицу (сейчас у построек модификатор 0 — см. вопрос); снос молотом — 1-011.
6. **Бот `dig_line`** проверяет счётчик: камня в сумке = сумма добычи со снятых скал.

Оставить 0,25 или поднять базу? Ярус инструмента — множитель (выше ярусом — вдвое быстрее)? До ответа — числа 0-034, ярус ×0,5.

## Принятые решения (1-010)

Числа и механика, зафиксированные при реализации (детали в коде: `DigTimes.cs`, `DigLoot.cs`, `Simulation.ApplyEditBatches`, `NetServer.Edits.cs`, `NetClient.Edits.cs`; тесты — `EditTests` `D01_S5_Dig*`).

1. **Формула времени**: `время = база × модификатор объекта ÷ (100 << min(2, ярус инструмента − ярус нужный))`, база **15 кадров** (0,25 с при 60 Гц), округление к ближайшему кадру. Потолок ускорения ÷4 считается **относительно нужного яруса** (кирка на два яруса выше — ×0,25, дальше не ускоряется). Модификатор 0 — «нельзя» (контракт 0-034: `FramesFor` = 0 → отказ).
2. **Модификаторы** (прикидка, ждёт подтверждения Автора): Rock ×100 (каменная кирка 15 кадров), Granite ×150 и ярус 2 (каменная — отказ «нужна кирка: медная»; медная 23, железная 11, золотая 6), Ore ×200 (каменная 30), Tree топор ×120 (18), Stump ×60, Bush топор ×50 и **руки** ×100 (15). Постройки — кирка ×800 (120 кадров ≈ 2 с, ответ на `[док]`-вопрос: модификатор дан, снос молотом ×200 — за 1-011).
3. **Руки** копают то, где в таблице нужный инструмент — руки (куст/трава): в `FramesFor` исключение `tier < req && !(руки && req==1)` — руки «яруса 1» и не отвергаются для своих объектов. Досягаемость: `Items.LengthUnits(None) = Reach.HandsUnits` (192, та же длина, что кирка — руки копают соседний тайл), `CopperPickaxe` → `PickaxeUnits`.
4. **Медная кирка** — предмет id 7, ярус `TierCopper` = 2; `Items.Count` = 8.
5. **Добыча детерминирована**: `DigLoot.DropFor(raw, x, y, seed)` = бросок `SplitMix64.Hash(x, y, id, WorldSeed)` по диапазону таблицы (скала/гранит — камень 1–2, залежь — медь 2–3, дерево — 3 древесины, пень — 1, куст — 1 волокно). Сервер и клиент (предсказание) считают одно и то же; выдача — атомарно в `Simulation.ApplyEditBatches` в том же такте, что правка; **двое копающих — добыча ровно тому, чья правка принята**; снос постройки — добычи нет (возврат по доле прочности — 1-011, хвост в `backlog`).
6. **`_preObj`**: добыча читает объект **до** применения пачки — предпросмотр старого объекта (`_preObj[i]`) захватывается в pre-цикле для всех правок чанка; после `ApplyEdits` тайл уже Empty, читать было бы нечего.
7. **Отказы** — новые `EditReply.ToolRequired = 11` («нужен топор»), `TierRequired = 12` («нужна кирка: медная»); человекочитаемую строку даёт `EditRules.Describe`, сервер отвечает строкой в отказе. Протокол **16 → 17** (золотые байты обновлены).
8. **Клиент**: своя сумка `Inv`/`InvVersion` из снимка (тип 26); `Inv` — свойство-структура, правка через копию + присваивание. Предсказание добычи — на своём завершении копания; откат по отказу — только если `InvVersion` с тех пор не менялся (снимок сервера главнее).
9. **Бот `dig_line`**: ячейку инструмента подбирает по таблице клиента (`ToolSlotFor`: топор для дерева, кирка для скалы); «нужен инструмент» в отказах — нормальная статистика (валы ответов при RTT 100). Бюджет тактов Big-теста (1000 скал, RTT 100) ×2: с 1-010 копание идёт временем (скала 8 кадров), а на полном прогоне Big-тесты делят ядра. Проверка приёмки: сумма бросков по всем «каменным» тайлам (`StoneTiles`: скалы в полосе + вне полосы + гранит) = камень в сумке копающего (и клиента, и сервера), откатов предсказания 0.
