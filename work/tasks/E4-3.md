**Ссылки:** модуль `work/modules/save.md` (читать перед шагом; модуль заморожен); `work/modules/net.md`
(характер уходов: обрыв связи, выход, вытеснение).

## Зачем
Шаг 4.3 плана (`work/PLAN.md`, этап 4 «вдвоём по сети»); приёмка **А**. Формат сейчас 17 (E3-3b).
После этапа 3 в сейве появились: личная капля (`PileField.Owner`), стрелы-кучи, добыча, луки,
очереди крафта, сундуки, постройки на сетке 0,5. Сквозной проверки «полный цикл игры →
перезапуск → всё на месте» нет; есть только частичные тесты по формам (форматы 6…17).
Разблокирует: 4.4 (приёмка вдвоём).

## Что делаем
1. **Сквозной тест перезапуска** (`tests/Orpheus.Tests/`, на настоящем `ServerHost`, как `C005_Craft_…`):
   сгенерировать мир → оба игрока играют (добыча, крафт в очереди, сундук с содержимым, постройки
   0,5, личная капля с владельцем, кровать как точка возрождения) → сохранение → **убить процесс
   сервера** → старт нового сервера на той же папке → вход обоих → хэш состояния совпадает
   с хэшем до падения; содержимое сундуков, очередь крафта (сворачивается в сумку — правило E2-3),
   позиция, сумка, кровать, владелец личной капли — на месте.
2. **Обрыв записи**: смоделировать падение посреди записи (прерванная запись временного файла:
   обрезать/оставить `*.tmp`, удалить переименование) → сервер стартует, берёт **прежний** файл,
   мир читается, ничего не «полуприменено»; второй вариант — битый основной файл (обрезанный) →
   понятная ошибка в логе и запасной/прежний путь по существующему поведению (как сейчас — записать
   в «Решения»).
3. Если тест вскрывает реальную потерю данных — чинить в `src/Orpheus.Save/` (формат при этом не
   менять, если достаточно порядка/атомарности; если формат трогать нужно — следующий номер +
   тест на настоящий файл прошлой версии + строка в `work/modules/save.md`).

## Правила
Модуль `save` заморожен: только починка фактической дыры. Атомарная запись (временный файл →
сброс на диск → переименование) не ослабляется; отложенная запись запрещена. Старый файл обязан
читаться. Пороги не ослаблять, `Assert` не удалять. Тесты не пишут в реальные папки Автора —
только во временные каталоги. Сети — `127.0.0.2`, `--public` никогда. Дочерние процессы — скрытый стол.

## Решения
- [док] Хэш сверяется косвенно: `OnLoaded` передаёт `StateHash.Compute(sim).Total` на момент загрузки
  (до первого такта, персонажи вне мира), а хэш начала записи — полное состояние (персонажи, очереди).
  Сравнивать их напрямую нельзя; проверяем номер поколения + такт + все факты мира (паттерн донора
  C-005 — массы).
- [док] Обрезка `.tmp` — на первом визите `Writing` (до байтов): кусок проба 512 байт, у малого файла
  (~260 байт на малом мире) «середины» нет; 0-байтовый `.tmp` — корректная модель обрыва.
- [док] `sim.AddPile` привязывает каплю к центру тайла — факт позиции берётся из мира на такте фактов.
- [док] Очередь крафта после рестарта НЕ продолжается, а сворачивается с возвратом в сумку (правило
  E2-3, `CharacterRoster.Restore`); тест проверяет сворот точно (пустая очередь + волокно 297 −
  3×верёвка), как донор C-005. Прежняя проверка «верёвка есть в мире» проверяла несуществующее правило.
- [док] Владелец личной капли в сейве — id сущности (формат 17); после рестарта персонажи — новые
  сущности с новыми id, перекладки нет → капля «чужая» всем. Дефект ядра вынесен в карточку
  `work/tasks/E4-3b.md`; здесь тест проверяет, что поле доезжает как записано.
- [док] Обрыв и сверка — по ПОСЛЕДНЕЙ ЗАВЕРШЁННОЙ записи, а не строго по такту фактов (поймано в
  общем прогоне 20.11: под нагрузкой CI в том же такте, что закончилась запись фактов, стартует
  новая — повод «перегрузка: такты не догоняется»; условие `LastDoneTick == FactsTick` пропускалось
  навсегда, сервер не оборвался). Теперь: обрыв на первой границе такта с завершённой записью не
  раньше такта фактов (`!InFlight && LastDoneTick >= FactsTick`); поколение, такт и факты очереди
  сверяются по записавшемуся поколению (`CrashNumber`/`CrashTick`), факты каждой записи снимаются
  на её такте начала (`_perTick`). Волокно/верёвка — по сумке + кучам (297 = волокно сумка+кучи +
  3×верёвка сумка+кучи), без предположений о вместимости сумки. Это не ослабление: проверяемое
  правило то же, привязка к фактическому содержимому диска.
- Крах-сентинел: обычное `Exception` из `ISaveHook` на потоке такта выходит из `ServerHost.Run`
  (catch ловит только IOException-семейство) → `Error` + `HasExited`; `SaveOnStop` при остановке
  с ошибкой не пишет. Проб после срабатывания обрывает и все последующие записи, чтобы останов
  с ошибкой не заменил оборванный файл.
