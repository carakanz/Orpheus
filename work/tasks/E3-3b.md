# E3-3b — 3.3: добыча со зверей (мясо, шкуры, личная капля)

## Зачем
Шаг плана 3.3 (`work/PLAN.md`), хвосты E3-3 и E3-6 (`work/next.md` L76):
сейчас с любого врага падает «мясо 2–5 (50 %)» + стрелы с лучника, всё общее.
По `06` 1.6 у зверей мясо 1–2 (100 %) и шкура (70 %), дропа с людей в срезе
нет (оболы — валюта, не предмет среза), и весь дроп врагов **личный**
(`06` 9, 11): видит и поднимает только владелец, через 10 мин исчезает
(срок кучи уже есть — `PileLifetimeTicks`). Шкуры волка — хвост E3-6.

## Что делаем
1. **Таблица дропа по архетипу** (`SpawnEnemyDrop`, `Simulation.Enemies.cs:488`):
   - `Beast` (волк): мясо 1–2 @100 %; шкура 1 @70 % (`06` 1.6 «Звери»).
   - `Ranged` (лучник): стрелы 2–5 @50 % (`06` 1.6 «Люди»).
   - `Melee` (разбойник): дропа нет (у людей в дропе только оболы — валюта).
   - Смерть не от игрока (`LastHitBy` не игрок): не дропаем.
2. **Личная капля**: поле `GroundPile.Owner` (int id сущности-владельца,
   0 = общий). Дроп с врага: Owner = `Brain.LastHitBy`. Реплика
   `SendPilesTo` (`NetServer.Items.cs:231`): чужие личные кучи не отправляем.
   Автоподбор (`Simulation.Piles.cs:204`): чужую личную кучу не подбираем.
   Кучи из сумки (`BagOp.Drop`), из копки (`DigLoot`) и стрелы — общие, Owner=0.
3. **Протокол 37 → 38**: `NetPile` + Owner; пересчёт `NetPile.Bytes`/`MaxBytes`.
4. **Сейв 16 → 17**: запись/чтение Owner у кучи (старые файлы — Owner=0).

## Не делаем (backlog [док])
- Клык (30 %), ядовитая железа/паутина (пауки), оболы — предметы/валюты вне среза.
- Броски на каждого участника в 40 т и поправка 1/f(n) (`06` 9/11) — экономика
  группы, этап 4; в срезе один бросок на убийцу (соло f(1)=1).
- Вожак ×2, диковина 2 %, ивенты без дропа — акты II–III.
- Хитин паука — паука в коде нет (E3-3: волк + лучник).

## Решения
- [док] Лучник: было «стрелы 1–3 @100 %», стало «стрелы 2–5 @50 %» по `06` 1.6;
  melee-разбойник дроп перестал давать (было мясо 50 %) — у людей по `06` только
  оболы, мяса у них нет.
- [док] Дроп только с убитых игроком (`LastHitBy` → игрок): despawn/удаление
  врага дропа не даёт (так и было).
- Личная куча для клиента ничем не отличается от общей — фильтр на сервере,
  клиент не меняется.
- [док] `StateHash`: Owner входит в хэш кучи только при Owner ≠ 0 (тег `0xE33B`,
  тот же приём, что C-031 с тегом `0xC031`) — голдены хэшей сцен без личной капли
  не двигаются.
- [док] Протокол 37→38 (`NetPile` + Owner u32, байт 18→22, MaxBytes 866→1058),
  сейв 16→17 (`PileField.Owner=10`, пишется только ≠0). Подняты assert'ы версий
  в 17 файлах тестов и голдены байтов куч в `GroundItemTests`.
- [док] На main (7d537b3) лежали два красных теста-регресса, воспроизведены на
  main-чекауте до начала работ: `C035_Codec_GoldenBytes_StrictRejects` (ассерт
  «протокол 36», а C-036 поднял до 37) и `CraftTests.E23_Net_GoldenBytes_CraftRequest_Reply_State`
  (`Assert.False(Codec.IsKnown(40))`, а тип 40 — пачка событий — занят с C-035).
  E3-3b их чинит (37→38; `True(IsKnown(40))` + `False(IsKnown(41))`).
- Тесты статистики (100 трупов) спавнят врагов вдали друг от друга: радиус
  слияния куч `PileMergeUnits` = 1 тайл — впритык капли сливались бы в одну.
- [док] В `-All` упал старый тест E3-3 `E33ArcherWolfTests.E33_Death_Drops`: он
  закреплял ПРЕЖНЮЮ таблицу дропа (еда 2–5 @50 % с разбойника, стрелы 1–3 @100 %
  с лучника) и убивал врагов самоударом — по новым правилам E3-3b такое убийство
  дропа не даёт (проверено на main-правилах карточки). Тест переписан под новые
  правила: разбойник рукой игрока — дропа нет; лучник рукой игрока — стрелы 2–5
  @50 %, Owner = убийца; самоудар — дропа нет. Проверка не ослаблена: мутация
  «лута нет» даёт 0 — стрела `InRange(2,8)` краснеет; добавлена проверка
  «не-игрок убил — пусто», которой раньше не было.
