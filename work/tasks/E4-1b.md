   (`--ui-demo combat-death`), где клик пустой (`DeathMenuFrame` требует `_args.FromMenu`) — гасить

## Решения
- 20.11: **корень потока исключений в меню** (найдён на живом прогоне): `InputState.Change(Mouse.current.leftButton, …)`
  кидает `ArgumentException: Cannot change state of bitfield control 'Button:/Mouse/leftButton'` каждый кадр —
  кнопка мыши в Input System битфилд, через этот API меняется нельзя; исключение из `Frame` вырывалось в юнити-цикл,
  `_demoPress` не сбрасывался → спам в Player.log (стек-трейсы переполняли лог). Фикс: полное состояние
  `new MouseState { position = … }.WithButton(MouseButton.Left, true/false)` + `InputSystem.QueueStateEvent`
  (press — наведение+кнопка, release — текущая позиция + кнопка снята). В пакете com.unity.inputsystem@2436e68c60c4
  расширений `press()/release()` для кнопок нет — только событийный путь.
- 20.11: `Application.runInBackground = true` ставится только под `--auto-menu-click` (тестовый путь),
  поведение обычных запусков не меняется.
- 20.11 [док]: снимок `E4-1_menu-new` несёт случайное зерно мира и в `shots.ps1 -Check` по байтам не совпадёт —
  оставляем как есть (зерно фиксируется в сцене только при необходимости; завязывать снимок меню на зерно нет смысла).
- 20.11 [док]: в ad-hoc дымовых прогонах на скрытом столе `Mouse.current == null` (мышиного устройства нет) —
  автоклик дублируется прямым путём кнопки `_demoPress`; поэтому в карточке и живой прогон, и прямой путь.
