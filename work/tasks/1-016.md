## Решения

**Соответствие модели.** `classify2(…, full=False)` модели `design_room/threads/01_world/worldgen_model_v2.py` → `src/Orpheus.WorldGen/BiomeStage.cs` (`BiomeStage.Run`), таблица → `BiomeTable.cs` (`BiomeRow`, `BiomeTables.Slice`), вызов — в `MacroGenerator.Generate` после этапа 2.

| Модель | C# | Отличие |
|---|---|---|
| `SLICE_SHARE`, строки `assign(take(...))` по порядку | `BiomeTables.Slice`: строка = биом, доля %, источник (`All`, `UpperQuarterH`), ключ (`H`, `M`, `C`, нет — остаток), направление | таблица — данные, порядок массива — приоритет |
| `take`: `np.argpartition` по ключу среди `un & allowed` | одна `Array.Sort` по `long`: (значение, для «наибольший первым» — 65 535 − значение) << 32 \| индекс | порядок полный: равные значения — по возрастанию индекса на любой машине и при любой сортировке; у `argpartition` при равных порядок не определён |
| `h >= np.quantile(h, 0.75)` | ровно round(N/4) ячеек с наибольшей h по всем ячейкам (до разметки), равные — по индексу | при непрерывных значениях — те же N/4 ячеек (для N = 16 384 квантиль между 12 287-й и 12 288-й) |
| `round(T/100 * N)` (округление Python к чётному) | `(доля · N + 50) / 100` | половин не бывает: N = (W/8)² делится на 4, доля · N ≡ 50 (mod 100) невозможно |
| номера `MEADOW … GATE = range(13)` | `Biome.Meadow … Biome.Pregate` — те же числа | дамп сравнивается без перекодировки |
| `one_world2`: `b[d ≤ 150] = MEADOW` | нет | это этап 7 «Очаг» (`01` 2), не этап 3; в сверке показан отдельно |

- **Этап 3 без случайных чисел:** потока этапа не нужно, результат — функция полей.
- **Полный набор:** таблицы этапа 3 ещё нет (пояса, Перекрёсток, вода — следующие карточки); у `BiomeSet.Full` биом остаётся `BiomeNone`, хэши полного набора меняются только версией генератора.

- **Хэш полей в полной точности** (замечание 1 П по 1-015): `FieldData.HashHex()` — SHA-256 H, M, C, Edge (u16 LE). Эталоны: 1024² срез, зерно 1 — `d47682c8…244a49de`; 2048² полный, 1 — `7b386117…ea1f451b`; 4096² полный, 1 (Big) — `deab6d0c…9eefd503`.
- **Приёмка 1.8 на срезе выполняется по построению:** доли — квантили, и у C#, и у модели каждый биом получает ровно round(доля · N) ячеек (пещерам всегда хватает верхней четверти: 8 < 25 и горы ещё не взяли). Разница — 0 п. п. на любом числе зёрен; содержательная сверка — форма карты (ближайшая к Очагу ячейка биома, число и площадь областей), она в таблице ниже. Вопрос `[док]` в backlog.

## Проверка (П)

**Итог: принято с замечаниями.** Проверено на `a88ef4b` (копия `r1016`). Замечание 1 не блокирует слияние (код верен, не хватает теста), но закрыть его нужно не позже 1-017, где та же сортировка пойдёт на 4096² и 8192² полного набора.

**Код.**
- `BiomeTable`: таблица — данные (`BiomeRow`: биом, доля, источник, ключ, направление; порядок массива — приоритет), `BiomeStage.Run` от набора не зависит. Смысл строк совпадает с `01` 2 «Набор «срез»» и с `classify2(full=False)`: пещеры 8 % по наибольшей c среди h в верхней четверти, горы 14 % по наибольшей h из оставшихся, лес 33 % по наибольшей m из оставшихся, луга — остаток. Доля — от площади мира (`ShareCount(%, N)`), кандидаты — только неразмеченные ячейки источника, `min(доля, кандидатов)` — как `take` модели. Верхняя четверть — по всем ячейкам до разметки, считается один раз (`??=`).
- Ключ `(v << 32) | (uint)индекс`: v ≤ 65 535 → старшая часть ≤ 2⁴⁸, индекс < 2²⁰ на 8192² (макрокарта 1024²) и < 2³² до W = 2¹⁹. Переполнения нет. Все ключи различны, порядок полный, `Array.Sort` (интроспективная, неустойчивая) даёт единственный результат: равные значения — по возрастанию индекса. `ShareCount` — в `long`.
- Мелочь: `BiomeTables.Slice` — `public static readonly BiomeRow[]`, элементы массива может подменить любой код (`Slice[0] = …`) — лучше отдавать `IReadOnlyList<BiomeRow>` или копию.

**Версия генератора 3 и сохранения.** `MacroGenerator.GeneratorVersion` пишется только в заголовок `MacroMap` (OMAP). К миру игры генератор v2 ещё не подключён: `WorldGenModule.Current` = `StubGenerator`, `WorldModel.GeneratorVersion` = 1. Загрузка мира (`ServerHost`) не перегенерирует, а читает `world.base` (`WorldSnapshot.LoadBase`, версия — из заголовка снимка под SHA-256). `WorldSave.Load` сверяет версию генератора, зерно и форму со снимком, а SHA-256 снимка — с `BaseSha256`; при расхождении — `InvalidDataException` (тест `D00_Save_ForeignWorld_Rejected` — по зерну и SHA, версия в том же условии). `WorldSnapshot.ApplyChanges` сверяет версию так же. Значит, 2 → 3 старые миры не ломает: снимок грузится как был, чужое сохранение явно отклоняется, тихого расхождения нет. На будущее: номера Stub (1) и Macro (2, 3) не пересекаются — так и держать при подключении; `MacroMap.FromBytes` версию не проверяет (это просто чтение данных), а любой путь «перегенерировать из зерна» должен сверять версию из заголовка с текущей.
