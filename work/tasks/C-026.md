# C-026 — хвосты C-025 в `tools\ci.ps1`: таймаут шага, параллельный грейс, экранирование в `Join-CmdLine`

Модули: `tools` (ci.ps1). Хвосты — замечания П C-025 (`work/backlog.md`, раздел «инструменты», строки «C-025 П з. 1» и «C-025 П з. 2, 3, 5, 6»). Ветка `task/C-026`, копия `.claude/worktrees/tc026`.

## Что найдено

1. **П з. 1 (главное):** `HiddenCi.Run` ждёт ребёнка `WaitForSingleObject(INFINITE)` — консольный ребёнок, который зависает, вешает прогон намертво; таймаута на шаг нет. `dotnet`/`testhost` stdin не читают — риск латентный, но ночной прогон без надзора висит тогда полностью.
2. **П з. 2:** грейс потоков после выхода процесса последовательный: `oTask.Wait(60000)` + `eTask.Wait(60000)` — худший случай 120 с на шаг, в «Решениях» C-025 записан грейс 60 с.
3. **П з. 6:** `Join-CmdLine` не экранирует `\` перед кавычкой по правилам парсера аргументов MSVC/CRT (n слэшей перед `"` → 2n+1 слэшей + `"`; хвостовые слэши аргумента перед закрывающей кавычкой удваиваются). Аргументы ci.ps1 этот случай сегодня не порождают — дыра латентная.

Замечание П з. 4 (ANSI env-блок портит не-ASCII) в этой карточке **не** делается — остаётся в бэклоге (проверка на PS 7 / скомпилированной сборке).

## Что сделать

1. Параметр `-StepTimeoutSec` (по умолчанию 3600) в `ci.ps1`; передавать в `HiddenCi.Run`: `WaitForSingleObject` с таймаутом; по истечении — `TerminateProcess(258)` + пометка в stderr шага «шаг превысил таймаут» + код 258 (шаг красный, CI падает). `TimeLimitSec` (общий бюджет) не трогать.
2. Грейс потоков — параллельный: `Task.WaitAll(oTask, eTask, 60000)` (худший случай 60 с).
3. `Join-CmdLine` — экранирование по правилам MSVC (см. выше), с проверкой на таблицах «аргумент → ожидаемая строка».
4. **Тест-гард** `-SelfTest`: прогон HiddenCi на «читающем stdin» (гард — `powershell [Console]::In.ReadToEnd()`, обязан завершиться быстро по EOF, не висеть; `cmd /c more` не годится — после EOF открывает `CONIN$`) и на зависшем ребёнке (`powershell Start-Sleep 59` с малым таймаутом — обязан умереть по таймауту кодом 258); таблицы Join-CmdLine. Код 0 — гард зелёный.
5. (выросло из п. 4) **Починка канализации stdin `HiddenCi`**: EOF по stdin не доходил до ребёнка (гард-читатель висел до таймаута). Лечение — схема `HiddenProcess.cs`: `STARTUPINFOEX` + `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` (ровно inR/outW/errW) + job (`CREATE_SUSPENDED` + `Assign` + `Resume`, по таймауту `TerminateJobObject`). См. «Решения».

## Решения

- Дефолт `-StepTimeoutSec` = 3600 с: самый долгий известный шаг — тест в `-All` (ночной, ~30 мин на загруженной машине); в 60 раз больше штатного быстрого CI (157 с) — ложных срабатываний не даёт, висячий процесс снимает за час.
- **Канализация stdin (`HiddenCi`) переделана на схему `HiddenProcess.cs` (STARTUPINFOEX + `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`).** Зонды 1–12 (`%TEMP%\opencode\probe*_c026.ps1`): в PS 5.1 `Add-Type` маршалинг `SECURITY_ATTRIBUTES{bInheritHandle=true}` в `CreatePipe` не доходит до Windows (`GetHandleInformation` reader → fR=1, бит наследования не выставлен) → conhost ребёнка не включает pseudoconsole → EOF по stdin не приходит никогда. Plain `STARTUPINFO` чинить бесполезно (probe4/10 — все варианты висят); канонический `System.Diagnostics.Process` в той же среде даёт EOF за 0,1 с. С списком ручек (ровно inR/outW/errW) — EOF за 0,1 с (probe12). Заодно ребёнок садится в job (`CREATE_SUSPENDED`+`Assign`+`Resume`), по таймауту `TerminateJobObject` снимает всё дерево (dotnet → MSBuild → testhost).
- Гард-читатель stdin в `-SelfTest` — `powershell -NoProfile -Command "[Console]::In.ReadToEnd()..."`, **не** `cmd /c more`: современный `more.com` после EOF открывает `CONIN$` и ждёт клавишу (гард висел бы всегда).
- env-блок остаётся ANSI-схемой C-025 (юникодный блок в Add-Type PS 5.1 получает отказ 577) — П з. 4 в бэклоге не трогается.
