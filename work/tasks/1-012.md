# 1-012 — двери: открываются сами, закрываются через 1 с, «закрыть сейчас», враг не проходит

**Поток:** М (правила `05` 2, сеть). **Ветка:** `task/1-012` (рабочая копия `.claude/worktrees/t1012`). **Веха:** 1 «Прототип» (`08` 3.1, недели 18–19).

**Зависимости:** после слияния **1-011** (дверь как постройка с ценой). Механику двери (шаги 1–4) можно начинать раньше — объект `ObjectId.Door` и флаг `DoorOpen` уже есть; проверки с врагом (шаг 5) — после **1-007**. **Параллельно можно:** 1-004…1-009 (разные файлы), 1-014, генератор, все К. **Ждут эту карточку:** 1-013, 1-026 (хижина с дверью).

**Цель:** хижина с дверью: игрок входит и выходит, не останавливаясь, дверь за ним закрывается, обычный враг её не открывает. Без двери нет приёмки 1.5 («за закрытой дверью — 0 урона») и 1.6.

**Ссылки:** `docs/05_base_building.md` 2.3 (таблица и правила: открывается сама игроку в 1 тайле, движущемуся к ней; закрывается через 1 с после того, как её тайл и соседние свободны; F — «закрыть сейчас», после — 1 с сама не открывается; враг выталкивается на сторону, откуда пришёл), 2.4 (края), 2.5 (сеть: предсказание открытия своим клиентом), 2.6 (ядро: без «держать открытой»), 2.7 п. 3–4; `docs/02_combat.md` 9.3 «Дверь и погоня», 9.8 п. 3, 7. Код: `src/Orpheus.Core/World/ObjectId.cs` (`Door`, `IsPassable(id, flags)`), `BuildRecord.cs`, `src/Orpheus.Core/Movement/Collision.cs`, `src/Orpheus.Core/Pathing/SimulationPathTerrain.cs`, `ClientWorld.Prediction.cs`.

## Шаги

1. **Состояние двери** у сервера: открыта / закрыта; открывается, когда игрок в 1 тайле и движется к ней; закрывается через 1 с, когда её тайл и соседние свободны от игроков. Смена — правка тайла по общим правилам рассылки (флаг в записи постройки).
2. **F — взаимодействие:** бит в кадре ввода; короткое нажатие у двери — «закрыть сейчас» (если на её тайле нет игрока), после — 1 с не открывается сама. Удержание «держать открытой» — потом (`05` 2.6).
3. **Предсказание:** свой клиент открывает дверь перед собой сам (не упирается при задержке) и показывает её открытой, пока сервер не подтвердил закрытие (`05` 2.5). Движение сквозь открытую дверь — общий код столкновений.
4. **Враги:** обычный враг дверь не открывает; проходит, если она открыта в тот такт, когда он ступает на её тайл; при закрытии враг на тайле двери выталкивается на сторону, откуда пришёл. Проходимость двери для поиска пути — по состоянию (событие смены тайла — для пересчёта в 1-013).
5. **Проверки с врагом** (после 1-007): разбойник вместо волка в сценариях 2.7 п. 4 и 9.8 п. 7.

## Принятые решения (Продюсер, 11.11 — по `05` 2, `02` 9.3; вопросы закрыты)

1. **Состояние двери — флаги записи** (`BuildFlags.DoorOpen` = «открыта», `DoorKeepOpen` — потом, ворота): смена состояния = серверная правка тайла (объект тот же, record с новым флагом) по общему каналу (`RequestEdit(..., requester: 0, tag: 0)`, прецедент `DamageBuilding`/`StepExpiry` из 1-011). Все потребители (коллизии `IsBlocked`, оба поисковика, LOS ударов, дельты чанков, сейв v6) уже читают `ObjectId.IsPassable(obj, record.Flags)` — новой plumbing проходимости нет.
2. **Список дверей:** активный список тайлов-дверей в `Simulation` (регистрация при постановке в `ApplyEditsCore` и один скан при загрузке мира; ленивая отписка — запись/объект больше не дверь). `StepDoors(tick)` — фаза в начале такта, рядом с `StepExpiry`.
3. **«Движется к ней» (вопрос `[док]` закрыт):** считаетеся от **центра** тайла (`Torus.TileOf(Mover.Position)`): игрок в 8-соседстве двери (включая диагонали, «в одном тайле») и вектор его фактического движения (velocity мувера) имеет составляющую **к двери** (знак проекции по оси, где |Δ| больше; стоящий на месте не открывает) → открыть. Тот же критерий для автозакрытия — «свободны тайл двери и 8 соседей».
4. **Автозакрытие:** с момента, когда тайл двери и соседи свободны от игроков, — 30 тактов (1 с); игрок вошёл раньше — таймер снимается. Закрытие, когда на тайле двери игрок/спутник, — не происходит (`05` 2.4).
5. **F («закрыть сейчас»):** новый бит ввода `InputButtons.CloseDoor = 1 << 3` (WireFrame 16-битный — формат кадра не растёт; протокол 18→19). Короткое нажатие: ближайшая дверь в 8-соседстве тайла игрока; если на тайле двери стоит игрок — отказ (2.4, строка «в проёме — не закрывать»); враг на тайле — выталкивается. После F-закрытия — замок 30 тактов (auto-open молчит). Удержание («держать открытой») — не в карточке.
6. **Выталкивание врага при закрытии:** цель — соседний тайл двери по направлению последнего движения сущности (`Mover` пишет `LastDir` такт в такт, детерминированно; в сейв не идёт, после загрузки — дефолт); если целится во что-то сплошное/занято — первый свободный сосед по детерминированному порядку (E,S,W,N); нет ни одного — закрытие в этом такте откладывается (дверь не «съедает» сущность). Сущности обрабатываются по порядку слотов.
7. **Враг:** дверь не открывает (мозг не пишет `CloseDoor`, автооткрытие — только игроки); проходит в открытую по общему коллизийному коду (проверка на такт шага — «открыта в тот такт, когда ступает»); при закрытии — п. 6. Проходимость для поиска пути — по флагу (уже); событие смены тайла — общий `ChunkRevised`/`InvalidatePaths`.
8. **Предсказание клиента:** локальный soft-режим: свой клиент при критерии п. 3 для своего персонажа красит дверь открытой (ставит флаг в локальную запись тайла) **без запроса серверу**; сервер откроет сам своим edit-каналом. Серверный `ChunkRevised`/`TileReply` с записью «закрыта» — авторитет: локальный флаг снимается (клиент «показывает открытой, пока сервер не подтвердил закрытие»). Запрос «закрыть сейчас» — обычный запрос правки (record-only, маска+ответ); отказ (в проёме) — общая вспышка.
9. **Пол-эффект «упирания» при RTT:** движение предсказанного персонажа через дверь использует локальную запись с предсказанным флагом (п. 8) → скорость у двери не падает; правок предсказания 0 (запросов на открытие нет).
10. **Отрисовка Unity:** `WorldView.ApplyCell` — дверь с `rec.IsDoorOpen` рисуется светлой/полупрозрачной заглушкой (свой спрайт — 1-024); `IsSolidAt` (превью пути) — перейти на 2-аргументный `IsPassable(obj, record.Flags)` (записи в `CellTile` есть).
11. **Сейв формата 6 не растёт** (флаги едут в 8-байтной записи); golden bytes протокола 19.
12. **F на клиенте — передний фронт** (Unity): `Keyboard.current?.fKey.wasPressedThisFrame` в `NetGame.Edits.cs` (курсорный обработчик правок); ищет открытую дверь в 8-соседстве своего тайла, свой тайл — отказ; шлёт `NetClient.CloseDoor(tile)` — предсказание record-only + запрос `TileOp.CloseDoor = 4` (18-байтное сообщение); сервер `OnCloseDoor` (chebyshev ≤ 1, свой тайл — отказ), ответ `Accepted` маска 1 / `NotAllowed` 0; откат — общий `ClientWorld.Resolve`. Предикция `_netRules.Solid` (ядро) уже флаг-aware — правки не требовалось.
13. **Правка состояния двери не списывает стоимость постановки**: исключение в `Simulation.PreEdit` (`obj == Door && HasRecord && preObj == Door` → без проверки ресурсов); иначе F-закрытие с пустой сумкой давало `NoResources` (найдено трассировкой).
14. **Отрисовка:** `WorldView.ObjectTile(Door)` — закрытая камнем (`_stone`), открытая — светлее (`DoorTile(open)` → `_meadow`); в `Fill` для двери читается `chunk.TryGetBuild` → `DoorTile(rec.IsDoorOpen)`. Свои спрайты — 1-024.
15. **host-smoke проход (приёмка «Unity host-smoke код 0»):** серверный ключ `--debug-door` ставит закрытую дверь в тайл `(cx − 3, cy − 1)` = 4 тайла к востоку от появления № 0 (серверная правка, без стоимости, пол не перекрашивается); клиентский `--smoke-door` включает его и в `NetSmokeCheck` требует: дверь открыта (автооткрытие шагом), пройдена, закрылась (автозакрытие 30 тактов). Скриптовый бег на восток (6 т/с) проходит дверь на ≈1,2 с, закрытие ≈2,5 с.

## Вопросы

- `[док]` «Движется к ней» (`05` 2.3) — по направлению ввода или по скорости? И «в одном тайле» — от края коллизии или от центра? Исполнитель записывает принятое в «Решения».
