# C-039 — утечка записей _deadAge в клиенте (хвост E3-4)

## Зачем
Хвост E3-4 (`work/next.md`, строка 3.4): «утечка записей `_deadAge` (backlog)».
`client/Assets/Scripts/Anim/NetAnimation.cs:239` — `Dictionary<int,float> _deadAge`:
запись заводится на каждую сущность, у которой заметили смерть (:224-226), и удаляется
только когда до неё доходит обход (:232). Сущности, которые умерли вне экрана и больше
не появляются в снимках, остаются в словаре навсегда. За «две ночи подряд» (приёмка 3.7)
словарь растёт. Разблокирует: 3.7.

## Что делаем
1. Найти, где `_deadAge` чистится; подтвердить утечку (вход в `_deadAge` без выхода
   для id, пропавших из снимка).
2. Починить: вычёркивать id, которых нет в текущем снимке/_known и чей возраст записи
   прошёл порог исчезновения (`DeathAnim.Gone`, трупная отрисовка 12 с — :599).
   Чистка — в существующем кадровом обходе, без новых таймеров.
3. Клиент Unity unit-тестов не имеет: проверка — `Orpheus.exe --anim-shots <папка>`
   (лента не изменилась), `tools\build_client.ps1 -Backend Mono -Smoke -HostSmoke` код 0,
   и снимки боевой сцены из `tools/shots.json` не поменялись (сверить с эталоном до правки).

## Правила
Только клиент. Ядро/сеть/сейв не трогать. Снимки смотреть глазами самому.

## Готово, если
Утечка закрыта (оценка: размер словаря в бою со спавнером не растёт после исчезновения трупов),
host-smoke 0, лента кадров та же, П принято.

## Состояние
Открыта 19.11. Ветка task/C-039, копия .claude/worktrees/tc039.

## Место остановки
19.11. Разбор готов. Утечка подтверждена: `Remote()` (NetAnimation.cs:184) вызывается каждый кадр из снимка
(NetGame.cs:774) для каждой сущности; запись `_deadAge[id]` растёт пока `HealthPct == 0` в снимке (:224-226),
удаляется только при `HealthPct != 0` (:232). Сервер держит труп 10,5 с (`Simulation.CorpseTicks`), снимает сущность
из снимка — `Remote()` больше не вызывается, запись заморожена навсегда. Смежные словари: `_remoteSeenFrame` чистится
в `ForgetGoneEnemies()` (:649-660, порог 60 кадров), `_remoteMelee`/`_remoteAct` — в `ForgetGoneMelee()` (:347) — туда
и встраивать чистку `_deadAge`. Признак «в снимке этот кадр» = `_remoteSeenFrame[id] == Time.frameCount`.
Правка (план): в `ForgetGoneEnemies()` после существующих обходов вычёркивать `_deadAge[id]`, если id не нарисован
в этом кадре и `DeathAnim.Gone(age, true)` (age ≥ 1,7 с — растворение кончено, рисовать нечего); вместе с записью
убирать призрак-манекен `_enemies[id]` (:599 corpse держит его скрытым вечно — Idle обнулён, сама чистка его не берёт),
иначе после снятия записи спрайт «оживёт». Чистка в существующем обходе, без таймеров.
Дальше: эталон (сборка в фоне `build\logs\c039_base.txt`, ленты `--anim-shots` + shots.ps1 `E3-1*`, `C-018*`) → правка →
сборка/smoke → ленты после → сверка глазами.

## Решения
- [док] Порог удаления = не нарисован в кадре + `DeathAnim.Gone(age)` (1,7 с): запись после растворения ничем не
  читается (Gone() и corpse-проверка :599 для растворенного трупа дают тот же «не рисовать»), удаление невидимо.
- [док] Записи, замороженные ДО 1,7 с (убит и вышел из окна снимка <1,7 с), остаются до переиспользования id
  (первый живой кадр снимает запись :232) — карточка требует порог «прошёл исчезновение», меньше не вычёркиваем:
  при возврате в окно труп обязан досмотреть падение с того же возраста.
- [док] Смежная течь найдена, НЕ правится (вне карточки): `_remotes` (ActorRig чужих, :37) и `_remoteShots` (:76)
  никогда не чистятся — candidate в backlog.
