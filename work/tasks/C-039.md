# C-039 — утечка записей _deadAge в клиенте (хвост E3-4)

## Зачем
Хвост E3-4 (`work/next.md`, строка 3.4): «утечка записей `_deadAge` (backlog)».
`client/Assets/Scripts/Anim/NetAnimation.cs:239` — `Dictionary<int,float> _deadAge`:
запись заводится на каждую сущность, у которой заметили смерть (:224-226), и удаляется
только когда до неё доходит обход (:232). Сущности, которые умерли вне экрана и больше
не появляются в снимках, остаются в словаре навсегда. За «две ночи подряд» (приёмка 3.7)
словарь растёт. Разблокирует: 3.7.

## Что делаем
1. Найти, где `_deadAge` чистится; подтвердить утечку (вход в `_deadAge` без выхода
   для id, пропавших из снимка).
2. Починить: вычёркивать id, которых нет в текущем снимке/_known и чей возраст записи
   прошёл порог исчезновения (`DeathAnim.Gone`, трупная отрисовка 12 с — :599).
   Чистка — в существующем кадровом обходе, без новых таймеров.
3. Клиент Unity unit-тестов не имеет: проверка — `Orpheus.exe --anim-shots <папка>`
   (лента не изменилась), `tools\build_client.ps1 -Backend Mono -Smoke -HostSmoke` код 0,
   и снимки боевой сцены из `tools/shots.json` не поменялись (сверить с эталоном до правки).

## Правила
Только клиент. Ядро/сеть/сейв не трогать. Снимки смотреть глазами самому.

## Готово, если
Утечка закрыта (оценка: размер словаря в бою со спавнером не растёт после исчезновения трупов),
host-smoke 0, лента кадров та же, П принято.
