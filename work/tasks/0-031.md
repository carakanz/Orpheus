# 0-031 — режим «сервер в потоке» и `IPlatformStorage` для клиента

**Поток:** Я (`ServerHost`, локальная связь) + М (сохранения через `IPlatformStorage`) + К (клиент Unity). **Ветка:** `task/0-031` (рабочая копия `.claude/worktrees/t031`). **Веха:** 0, платформенный слой (неделя 11).

**Зависимости:** **после слияния 0-024** (запуск сервера из клиента, ключи, режимы клиента) **и 0-025** (цикл такта, часы, заморозка в `ServerRun`); желательно после 0-030 (метрики такта переезжают вместе с циклом). **Параллельно можно:** с 0-027, 0-028, 0-029 (сервер в них — `NetServer`, не цикл `ServerRun`), 0-023. **Ждут эту карточку:** приёмка 0.12 (IL2CPP — после модуля, который ставит Автор).

**Цель:** `07` 1.6 и 2.3 — `ServerHost` из той же библиотеки работает в потоке игры, клиент ходит к нему через локальную связь; режим есть с первого дня и проверяется в CI. Сохранения и загрузка в этом режиме — только через `IPlatformStorage` (на ПК — `PcStorage`). На ПК по умолчанию остаётся отдельный процесс (0-024).

**Ссылки:** `docs/07_multiplayer_tech.md` 1.6 (строки «Код», «Сервер на консоли», «Сохранения»), 1.3 (`netstandard2.1`, без рефлексии), 1.9 п. 5, 2.3 (строка «На консоли»); `docs/08_roadmap.md` 3.0 (строка «Платформенный слой», приёмка 0.12), 4.2 (нед. 11); `src/Orpheus.Server/ServerRun.cs`, `TickClock.cs` (P/Invoke таймера), `WorldSaver.cs`, `JsonLog.cs`, `src/Orpheus.Net/Transport/LoopbackTransport.cs`, `src/Orpheus.Save/IPlatformStorage.cs`, `src/Orpheus.Platform.Pc/PcStorage.cs`; `client/Assets/Scripts/GameBoot.cs`, `ClientArgs.cs`; `tools/build_client.ps1` (DLL в `Assets/Plugins/Orpheus`). `work/backlog.md`: «[сеть] `LoopbackTransport` выделяет массив на каждый пакет…» (П по 0-008 з. 9).

## Шаги

1. **`ServerHost`** — цикл сервера (такт, `NetServer`, сохранение, журнал, часы, метрики) из `Orpheus.Server` в сборку `netstandard2.1` без P/Invoke и `Console`: таймер высокого разрешения (`TickClock`, kernel32) — за интерфейсом платформы с реализацией «ПК»; лог — в `TextWriter`/приёмник. `OrpheusServer` — тонкая оболочка над `ServerHost`; поведение и ключи не меняются (тесты сервера зелёные без правок).
2. **Локальная связь** без выделений на пакет (backlog): пул буферов в `LoopbackTransport`; тест в `AllocationTests`. Потокобезопасность: сервер в своём потоке, клиент — в потоке игры; очередь между ними — без блокировок на каждом пакете (или с одной короткой — записать).
3. **Сохранения через `IPlatformStorage`:** `ServerHost` получает хранилище снаружи (на ПК — `PcStorage`); никаких прямых `File.*` в пути сохранения и загрузки (тест или анализатор).
4. **Клиент Unity:** режим «сервер в потоке» ключом (`ClientArgs`): `ServerHost` в потоке, клиент — через локальную связь тем же `NetClient`; сохранение и загрузка — через `PcStorage`. DLL `Orpheus.Server`-ядра (новой сборки), `Orpheus.Save`, `Orpheus.Platform.Pc` — в `Assets/Plugins/Orpheus` скриптом сборки.
5. **Тест CI без Unity** (`D07_S1_9_5_*`): `ServerHost` в потоке + `NetClient` по локальной связи — N тактов (ускоренно), такт держится (отставание ≤ 3 тактов), автосохранение через `IPlatformStorage` (`PcStorage` во временной папке и хранилище в памяти), загрузка заново — хэш мира тот же.
6. **Unity Mono:** «сервер в потоке» — одиночная игра 10 мин в пакетном режиме (`--smoke`-сценарий), такт держится, сохранение и загрузка проходят; IL2CPP — когда Автор поставит модуль (`work/next.md`, «Ждёт Автора»), тогда же 0.12 целиком.

## Решения (исполнитель)

- Новая сборка `src/Orpheus.ServerHost` (`netstandard2.1`, пространство имён `Orpheus.Server` — тесты сервера компилируются без правок). Туда `git mv`: `ServerOptions`, `WorldSaver`, `ServerMetrics` (без отчёта и процесса ОС), `TickMetrics`, `HostSession`, `HostLockWriter`, `CountingTransport`; `ServerRun` → `ServerHost` (тот же цикл). Платформа — снаружи через `ServerHostServices`: `IPlatformStorage`, часы `TickPacer` (переносимо, `Thread.Sleep`), `IServerLog`, `IRuntimeStats`, открытие журналов, `ISaveHook`, `LocalTransport`, событие `Ready`.
- `OrpheusServer` (`net9.0`) — оболочка `ServerRun`: `JsonLog : IServerLog`, `PcStorage`, `PcTickClock`, `ProcessRuntimeStats` (GC .NET 9), `SaveCrashHook : ISaveHook`, `ServerReport` (`--report`). Ключи и поведение прежние.
- `TickClock` (P/Invoke kernel32/libc) → `Orpheus.Platform.Pc/PcTickClock.cs`, наследник `TickPacer`; `Platform.Pc` ссылается на `ServerHost`; боты берут `PcTickClock` (ссылка на файл убрана).
- Правила ORP (детерминизм) на `ServerHost` не включены: это цикл вокруг симуляции, часы и метрики настенные по делу (как в `Platform.Pc`). Вместо них — `D07_S1_6_ServerHost_CoreRules_NoPlatformCalls`: netstandard2.1, без Unity/Json/Emit/`Orpheus.Platform`, в исходниках `ServerHost` и `Save` нет рефлексии, P/Invoke, `Console`, `Process`, `File/Directory/FileStream/StreamWriter`.
- `NetServer` не тронут (параллельно 0-033). Строка backlog «[метрики] разделить часть net внутри NetServer при переносе в ServerHost» — не сделана по той же причине.
- `LoopbackTransport`: пул буферов получателя (классы 64 Б…64 КБ), связи — снимок массива (копия при записи), на пакет одна короткая блокировка (очередь получателя), в `Poll` — две на вызов. Интерфейс тот же.
- Клиент: `--server-thread` (сам включает `--single`), `ThreadServer.cs`, `NetGame.Thread.cs`; в `NetGame.cs` — 4 строки (старт, кадр, выход, проверка smoke). `build_client.ps1 -ThreadSmoke [-ThreadSmokeSeconds N] [-NoBuild]`.
- Вопросы `[док]` — допущения в `work/backlog.md`: CI = `dotnet test` + smoke сборки; `ServerHost` — netstandard2.1, остальное на net9.0; 10 мин — ботом-сценарием net-smoke.
