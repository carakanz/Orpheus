# 1-028 — F по закрытой двери = продление замка (без правки)

Статус: в работе. Ветка `task/1-028` (носитель правила: двери/замок — правило 1-012).
Вынесено из 1-026 (карточка ботов не правит ядро; слияние 1-028 — раньше 1-026).

## Цель

Боту `build_room` (1-026) нужно держать дверь закрытой всю ночь: он жмёт F каждый кадр.
F по уже закрытой двери раньше отвергалась (или проходила как no-op правка со спамом
рассылок), и автооткрытие шагом открывало дверь, когда замок истёк. Правило:
**F по закрытой двери продлевает замок и не порождает правку.**

## Приёмка

1. F (локальная/по сети) по закрытой двери в радиусе 1, не в проёме → принято,
   замок `_doorLockUntil = tick + 1 + DoorLockTicks` (30), запись не тронута.
2. В продлённом замке автооткрытие шагом молчит; F убрали → по истечении замок
   открывается шагом (вечной блокировки нет).
3. F по открытой двери — без изменений (закрыть + замок).
4. Клиент: по закрытой двери запрос уходит без предсказания (предсказывать нечего);
   по открытой — предсказание как раньше.
5. F-спам по закрытой двери не порождает рассылок правок (ChunkPatch) сервером.
6. Протокол 20, сейв v6 — без изменений.

## Реализация

- `Simulation.BeginDoorClose`: ветка `fromF && !rec.IsDoorOpen` → замок + `return true`
  до общей проверки замка и до no-op ветки закрытия.
- `NetClient.CloseDoor`: предсказание (снятие битов открытости) — только по открытой
  двери; запрос шлётся всегда.

## Тесты

- `DoorTests.D12_F_On_Closed_Door_Extends_Lock` — стенд: закрыли F; на истечении замка
  спам F+шаг к двери — дверь не открывается; F убрали — открывается шагом после замка.
- `EditTests.D12_S2_11_CloseDoor_On_Closed_Sent_NoPrediction_Accepted` — сеть: запрос
  уходит, предсказания нет, ответ «принято», запись закрыта; счётчик PatchCounter:
  F-спам (20 запросов) не увеличил число ChunkPatch.

## Мутации

- M1 — ветка продления убрана: **красная** (`D12_S2_11`: PatchCount 2 ≠ 1 — no-op правки
  рассылаются). На стенде при этом зелёная: старый код принимает F по закрытой двери
  после истечения замка как no-op правку + замок → поведение идентично. Вывод: настоящий
  фикс — клиент (по закрытой двери запрос раньше не уходил вовсе), серверная ветка —
  оптимизация (нет спама no-op рассылок при F каждый кадр).
- M2 — ветка принимает без проставки замка: **красная** (`D12_F_On_Closed_Door_Extends_Lock`
  — дверь открывается шагом в «продлённом» замке).
- M3 — клиент не шлёт запрос по закрытой двери: **красная** (`D12_S2_11` — `req == 0`).
