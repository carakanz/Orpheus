# 0-010 — клиент рисует мир: окно чанков, персонаж, камера, шов без рывка

**Поток:** К (клиент). **Ветка:** `task/0-010` от `main`. **Веха:** 0, недели 3–4 (локально, без сети — сеть подключит следующая задача клиента).

**Цель:** в Unity виден настоящий мир из ядра: клиент генерирует мир по зерну через `StubGenerator` (DLL ядра в `Assets/Plugins`), рисует окно чанков вокруг персонажа двумя Tilemap на чанк, персонаж-заглушка ходит по WASD через `Mover` ядра (локальный такт 30 Гц), камера следует с зумом, переход через шов тора — без рывка.

**Ссылки:** `docs/07_multiplayer_tech.md` — 1.2 (клиент: Tilemap, свет — пока не нужен), 3.2 («плавающее начало» на клиенте), 3.5 (окно чанков 6 × 4 у клиента, выход 8 × 6), 2.9 (интерполяция — между тактами 30 Гц и кадрами); `docs/00_vision.md` 5.1 (тайл 128 px в исходнике, 48 px на экране при 1080p, зум ×0,6…×1,0); `docs/08_roadmap.md` 3.0 строка «Клиент»; `work/refs/world.md`, `work/refs/movement.md`; правило временных ассетов — `CLAUDE.md`.

## Шаги

1. `tools/build_client.ps1` кладёт свежие DLL ядра (`Core`, `WorldGen`) в `client/Assets/Plugins/Orpheus/` — проверь, что конвейер из 0-002 работает с нынешним ядром.
2. Временные тайлы по правилу `CLAUDE.md`: пол «луг», пол «камень», объект «дерево», объект «скала» (`TEMP_*.png`, 128 px, пурпурный уголок, строки в `art/manifest.csv`), генерация — `tools/make_temp_assets.py`.
3. `WorldView`: два Tilemap на чанк (пол, объекты), заливка `SetTilesBlock`; окно 6 × 4 вокруг камеры с выходом 8 × 6 (гистерезис как у `ChunkWindow` ядра — используй его); переиспользование Tilemap из пула при сдвиге окна.
4. «Плавающее начало»: координаты Unity — относительно чанка-якоря рядом с персонажем; при пересечении шва и при уходе якоря далеко — сдвиг начала без видимого рывка (Tilemap и персонаж сдвигаются вместе).
5. Персонаж-заглушка: ввод WASD/стрелки/геймпад (Input System) → кадр ввода → `Mover` в локальном такте 30 Гц → интерполяция позиции в кадре; камера следует, зум колесом ×0,6…×1,0.
6. Сцена `Boot`: зерно и размер (1024²) из аргументов или по умолчанию; режим `--smoke` теперь ещё прогоняет персонажа по прямой через шов по X и по Y (скриптовый ввод) и проверяет: позиция по ядру совпала, рывок в кадре ≤ 6 т/с × 1/30 с × 1,1.
7. Сборка: `tools/build_client.ps1 -Backend Mono -Smoke` зелёная (IL2CPP — пока модуля нет, см. `work/backlog.md`).
8. Скриншот: из сборки в режиме `--screenshot <путь>` — кадр мира с персонажем (через `ScreenCapture`), путь — в карточку; без вывода окна поверх других приложений не обязательно — сборка может открыть окно ненадолго.
