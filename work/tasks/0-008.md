# 0-008 — транспорт LiteNetLib, имитатор связи, протокол, вход

**Поток:** Я (ядро и сеть). **Ветка:** `task/0-008` от `main`. **Веха:** 0, недели 3–4.

**Цель:** клиент без графики (бот) подключается к `OrpheusServer` по UDP, проходит вход, шлёт ввод 60 Гц и получает полные снимки 30 Гц; связь можно портить своим имитатором (задержка, разброс, потери, дубли, перестановка) детерминированно по зерну — в Release тоже.

**Ссылки:** `docs/07_multiplayer_tech.md` — 1.3 (модули, LiteNetLib 2.x), 1.6 (транспорт за интерфейсом `ITransport`), 2.3 (запуск), 2.4 (такты и часы), 2.10 (транспорт и протокол: каналы, размеры, настройки), 4.2–4.3 (виды сущностей, снимки — только полные, дельты — следующей задачей), 11.3 (боты), 2.13 приёмка п. 1, 5, 6 (для движения); `docs/08_roadmap.md` 3.0 строки «Сеть», приёмка 0.6; `work/refs/movement.md`. Числа для LiteNetLib (из разбора opencode, сверь с 2.10): MtuOverride 1232, полезная нагрузка 1228, бюджет снимка 1200, ChannelsCount 5, DisconnectTimeout 10 000, PingInterval 1 000, события — в потоке такта; пакет ввода — 38 байт, 60 Гц, 4 кадра (текущий + 3 прошлых).

## Шаги

1. `ITransport` в `Orpheus.Net` (`netstandard2.1`) + реализация на LiteNetLib 2.x (закрепи версию, проверь, что собирается под `netstandard2.1` и будет работать в Unity IL2CPP — без недоступных там вызовов; запиши в карточку) + `LoopbackTransport` (в памяти, для тестов и «сервера в потоке»).
2. Имитатор связи — обёртка над `ITransport`: задержка, разброс, потери, дубли, перестановка; случайность от зерна (`DetRandom`); работает в Release.
3. Протокол: заголовки, номера, кодек сообщений своим двоичным форматом (без рефлексии и `System.Text.Json`); сообщения: вход (имя, версия), приём/отказ, ввод (4 кадра), полный снимок (сущности в окне — пока все сущности рядом), часы (номер такта сервера).
4. Сервер: приём подключений, вход, сущность игрока, ввод → `Mover` в такте (0-006), полный снимок каждые 33 мс; клиентский бот: подключение, ввод от `wander`, приём снимков, предсказание пока не нужно — только применять снимки.
5. `Orpheus.Bots`: `--connect host:port --count N --script wander --rtt --jitter --loss --minutes --report <json>`.
6. Тесты `D00_Net_*`: кодек — туда-обратно побайтно для каждого сообщения; размер снимка ≤ 1200 при 8 игроках; имитатор — заданные потери и задержка в допуске на 10 000 пакетов, по зерну повторяемо; интеграция на `LoopbackTransport`: 2 бота входят, двигаются, видят друг друга в снимках; на UDP (127.0.0.1) — 2 бота 60 с, RTT 100, потеря 1 %: ни одного отключения, клиент видит своё положение из снимка с отставанием ≤ 0,5 тайла (без предсказания — сверка по такту).

## Чек-лист приёмки

- [ ] Бот входит на сервер по UDP и получает снимки 30 Гц; отказ входа при несовпадении версии.
- [ ] Имитатор связи работает в Release и повторяем по зерну (тест).
- [ ] Снимок 8 игроков ≤ 1200 байт; кодек без рефлексии, анализатор чист.
- [ ] 2 бота × 60 с, RTT 100 мс, 1 % потерь — 0 отключений (тест `Category=Big` или отдельная команда в карточке).
- [ ] `tools\ci.cmd` зелёный ≤ 60 с.
