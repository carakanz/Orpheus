# C-035: пачка событий такта (урон/снаряд/взмах) + лимит куч-стрел

Ветка `task/C-035`, копия `.claude/worktrees/tc035`, база `main e729cf3`.
Пункт 8 `work/opencode_start.md` (хвосты E3-2/E3-1/C-031).

## Цель
1. Сообщения «урон» (37), «снаряд» (38), «взмах» (39) за такт — **одним сообщением на
   получателя** (новое «пачка событий» (40)), а не по сообщению на каждое событие.
   Ночной бой: десятки событий такта × несколько игроков рядом = сотни надёжных
   сообщений канала 2 за такт; пачка — одно.
2. Ограничить отправку куч-стрел за такт (хвост C-031): при входе в обзор с тысячами
   воткнувшихся стрел сервер гонит тысячи/48 ≈ десятки сообщений 27 за такт (~180 КБ).
   Лимит новых куч на игрока за такт — растягивает выгрузку обзора на несколько тактов.

Протокол: **36** (main после слияния E3-6 = 35; здесь следующее число). Сохранение не трогается.

## Решения
- [док] `PilesEnterPerTick` = 48 (одна пачка 27/такт/игрок): вход в поле 5000 стрел —
  выгрузка ~104 с при 30 тактах/с; числа предварительные, померить в тесте.
- [док] Смерть/возрождение (24/25) вне пачки: их мало (единицы за такт), порядок
  относительно урона критичен для экрана смерти.
- `EventBatchMessage.Write` проверяет **недобор** записи (`<`), а не «лишнее»: записи
  в staging лежат подряд, размер каждой берётся из схемы, «лишнее» после тела —
  следующая запись, а не хвост. Битая запись (неизвестный вид/обрезанный) —
  `ProtocolException` из `RecordBodyBytes` оборачивается в `InvalidOperationException`
  (контракт Write: ошибка кода сервера, не входящий пакет).
- Тест смерти: `AddEnemy` — манекен (сам не замахивается, 1-007) → `AddMeleeRogue`
  (удар 10, период 33 т). Тест лука: `rig.InputOf` принимает `NetClient` — атакуют
  только «лучник», стрелы свидетелей не портят счётчик пачек. Оп снаряда в
  голден-буфере — индекс 16 (запись снаряда начинается с 15).
