## Шаги

1. **Заморозка для тестов:** отладочный ключ сервера по образцу `--debug-save-*` (например, `--debug-freeze <такт>:<мс>`) и то же в тестовом стенде. Заморозка — **всего процесса** (как сборка мусора или антивирус): в тесте процесс сервера приостанавливается снаружи; если получится только поток такта — записать в «Решения», чем это мягче.
2. **Часы после фриза** (2.4): сервер отстал больше чем на 3 такта — «часы: кадр N» по каналу 2 (есть, `BroadcastClock`) **и в заголовке снимка**; клиент переставляет оценку сразу. Отставание до 3 тактов догоняется, больше — не догоняется (есть в `TickClock`, проверить тестом).
3. **Часы клиента** (2.4): оценка текущего кадра сервера — из пинга (раз в 1 с) и заголовка каждого снимка + owd; сглаживание — поправка хода своих часов на 1 %; ошибка > 100 мс — перестановка сразу. Номер кадра ввода — по оценке, L = 0 (опережение — недели 14–15). Часы показа чужих (`RemoteInterpolation`, 0-021) — отдельные, не трогать.
4. **Очередь кадров сервера** (0-019) с новыми часами: на ровной связи выбросов 0; потолок ждущих при спешащих часах — срезать до 4–6 кадров (backlog, П по 0-019 з. 2); запас 20 закрепить числом в тесте (П по 0-019, повт. з. 1).
5. **Тайм-ауты при фризе:** LiteNetLib `DisconnectTimeout` 10 с — 2 с проходит; свои тайм-ауты (стоп 0-015 — по такту сервера, «нет связи» в клиенте) не отключают. Тайм-аут входа для соединения без входа (backlog, П по 0-008 з. 8) — добавить так, чтобы фриз 2 с его не вызывал.
6. **Боты с предсказанием** (11.3): `NetBot` в `Orpheus.Bots` — с `LocalPrediction`, метрика «расхождение предсказанной позиции с серверной в тот же кадр» на каждом кадре; отчёт `--report`: доля кадров ≤ 0,5 тайла, наибольшее, правок.
7. **Тесты:**
   - CI (связь в памяти, `D07_S2_13_5_*`): заморозка 2 с посреди движения — 0 отключений; первый применённый кадр ввода после разморозки — ≤ 1 с (≤ 30 тактов); клиент получил «часы» и переставил оценку; стоп после обрыва — ровно 6 тактов (0-015 зелёный без правок);
   - `-All` (UDP, `D07_S2_13_1_*`): Big UDP 2 бота × 60 с, RTT 100, 1 % — расхождение ≤ 0,5 тайла в ≥ 99,9 % кадров, плюс одна заморозка 2 с посреди — 0 отключений;
   - полный прогон 0.6 — 30 мин, 2 бота, RTT 100, 1 %, с заморозкой 2 с на 10-й минуте — скриптом или ключом длительности, числа в «Замер».
