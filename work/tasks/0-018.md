**Сеть (LiteNetLib 2.1.5, пробная программа вне репозитория, реальные соединения):** `Start(IPAddress v4, IPAddress v6, int port)` привязывает IPv4-сокет к v4 и IPv6-сокет к v6 на одном порту. Подключались: сервер на петле ← клиент (`Start(Loopback, IPv6Loopback, 0)`) к `127.0.0.1`, `::1`, `localhost` — везде соединение есть; сервер на всех адресах ← клиент на петле к `::1` и `localhost`, а также обычный клиент к `127.0.0.1` — есть; сервер на петле при `IPv6Enabled=false` — есть. Недоступный IPv6-адрес (привязка падает с AddressNotAvailable) `Start` переживает: пишет в лог, возвращает `true`, IPv4 работает, — значит система с выключенным IPv6 не ломает ни сервер, ни клиент. К удалённому хосту и сервер `--public` идут по прежним веткам `Start()` / `Start(port)`, то есть как раньше. Ожидаемое следствие: клиент к собственному LAN-адресу машины на сервер по умолчанию не подключится (нужен `--public`).
