# C-040 — дверь без заказчика заменяет стену без возврата (хвост C-029)

## Зачем
Хвост C-029 (`work/next.md`, строка C-029): «дверь без заказчика заменяет стену без возврата».
При постановке двери поверх стены в режиме стройки, если ставить некому (нет заказчика/персонажа
в радиусе — путь через бота/правки такта), стена сносится, а оплаты/возврата двери нет —
масса мира не сходится. Ядро (`src/Orpheus.Core/Sim/Simulation.Build.cs`).

## Что делаем
1. Найти путь постановки двери (`ApplyBuild`/постановка двери поверх стены) и ветку «заказчика
   нет/не в радиусе» — воспроизвести тестом: стена есть → правка ставит дверь → стена удалена,
   предмет двери не списан (или списан без возврата стены — уточнить по коду).
2. Починить по правилу C-029 (проверка «заявитель жив и в радиусе» в такте, как `ApplyChestOp`):
   отказ с кодом, стена цела, масса не меняется.
3. Тест red→green в `tests/Orpheus.Tests` (файл Build*/Door*); сверить с ночными ботами
   (`night_camp`/`build_room` — не должны сломаться).

## Решения
- Дефект: возврат стены (`ReturnReplacedWall`) в `ApplyEditBatches` (Simulation.Edits.cs ~419–440) выполняется только когда `Requester > 0`; правки мира (`RequestEdit`, заявитель 0) ставили дверь на стену и молча её сжигали.
- Проверка «заявитель жив и в радиусе» добавлена в **PreEdit** — так же, как в `ApplyChestOp` (Simulation.cs ~3034). PreEdit вызывается в тике и из очереди, и из `ApplyEditBatches` — закрывает оба пути. Отказ до списания билда: ничего не тратится.
- Новый код: `EditResult.NoRequester = 9` (TileEdit.cs). Это только SimEvent/лог: проводимый формат `NetMsgEditResult.Result` (byte) не меняется, клиентские коды `EditReply` не меняются.
- `EditRules.FromResult`: `NoRequester → EditReply.OutOfReach` («далеко») — путь игрока этот код не порождает (клиентские правки всегда с заявителем), карта нужна для полноты.
- Радиус = `EditRules.InPlaceRadius` (6 клеток) — то же условие, что у `BuildCells.CheckPlace` для «дверь на стене»; признак стены — `_preObj[i] == ObjectId.Wall`. Живость — по слоту (`SlotOf` + `Alive`), как в ChestOp.
- Проверка срабатывает только для «дверь поверх стены» (постановка и смена состояния двери на стене): постройку и ремонт стены игроком не трогает (там стена остаётся стеной, возврата предметов нет); путь клиента этот код не порождает (заявитель в радиусе проходит `BuildCells.CheckPlace`).
- Ночные боты не затронуты: `night_camp` — без дверей; `build_room` ставит дверь на пустую клетку (планографист пропускает дверную клетку в Walls); `--debug-door` — дверь на траве.
