## Шаги

1. **`IServerLauncher`** — интерфейс в сборке `netstandard2.1` (рядом с `ITransport` или в модуле платформы — выбрать, записать в «Решения»); реализация «ПК» в `Orpheus.Platform.Pc`: путь к `OrpheusServer`, ключи — путь к миру, режим (одиночная / хост), свободный порт, одноразовый токен хозяина (2.3). Порт и готовность сервер сообщает сам (порт 0 → выбранный порт; строка в stdout или файл-замок) — без паузы «на всякий случай».
2. **Файл-замок мира** (7.6): сервер пишет в папку мира порт и токен хозяина, удаляет при штатном выходе; игра хоста после своего падения находит работающий сервер по замку и подключается. Через `IPlatformStorage`, если ложится в его интерфейс; иначе — записать почему.
3. **Ключи сервера:** токен хозяина (вход с токеном — флаг «хозяин» у игрока; ролей ещё нет), режим одиночной/хоста; без «Открыть для друзей» сокет только на петле (0-018).
4. **«Открыть для друзей»** (2.13 п. 9): по команде хозяина сервер начинает слушать UDP на всех адресах — тот же мир, такт не прерывается, уже вошедшие не переподключаются. UPnP — не в этой карточке.
5. **Падения** (2.3, 7.6): клиент хоста упал — сервер работает 60 с, остальные играют; хост вернулся за 60 с — входит в тот же мир; не вернулся — «хост вышел»: сохранить, разослать, завершиться. Игроков, кроме хоста, нет — сохранить сразу и ждать те же 60 с. Сервер упал — клиент показывает сообщение (текст — вопрос ниже) вместо зависания.
6. **Клиент Unity** (после 0-021): режимы «одиночная» и «хост» (ключами `ClientArgs`; меню — заглушка) запускают сервер через лаунчер и подключаются; `OrpheusServer` кладётся рядом со сборкой клиента (`build_client.ps1`). Что делать с нынешним офлайн-режимом (ядро в Unity без сервера) — вопрос ниже; до ответа офлайн-`--smoke` не ломать.
7. **Тесты без Unity** (`D07_S2_3_*`, `D07_S2_13_9`, `D07_S1_9_7`): «игра хоста» — отдельный процесс-бот с токеном хозяина:
   - лаунчер запускает собранный `OrpheusServer`, бот входит хозяином; второй бот входит после «Открыть для друзей» — мир не перезапускался (такт и хэш идут подряд);
   - процесс хоста убит — второй бот играет, 0 отключений; хост перезапущен и находит сервер по замку за ≤ 60 с — тот же мир;
   - хост не вернулся — сервер сохранил мир и вышел через 60 ± 1 с; поколение сохранения целое.
   В помощнике запуска сервера — правка из backlog (`HasExited` не заслоняет исходное падение).
8. **`tools/playable.ps1`** (backlog, П по 0-012): коды выхода View, ботов и сервера проверяются; зависший сервер не остаётся жить; порт — свободный, не 20000 жёстко.

## Решения (исполнитель, 07.11)

- **`IServerLauncher`** — в `Orpheus.Net` (`Orpheus.Net.Hosting`, рядом с `ITransport`): запрос `ServerLaunch` (папка мира, создать/зерно/размер, режим `Single|Host`, порт 0, адрес и порт «Открыть для друзей», ожидание хоста), `IServerInstance` (порт, токен, номер процесса, `ReadySeconds`, `HasExited`, `Stop`/`Kill`), `FindRunning(папка)` по файлу-замку. Реализация «ПК» — `Orpheus.Platform.Pc.PcServerLauncher` (Platform.Pc теперь ссылается на Net): `.exe` или `.dll` через `dotnet`, токен — 128 бит `RandomNumberGenerator`. Готовность — строка `orpheus-ready port=P` в stdout сервера (порт 0 → выбранный ОС), без пауз; вывод читается до конца жизни процесса.
- **Файл-замок** — отдельный `host.lock` (порт, токен, номер процесса, режим, порт «для друзей») через `IPlatformStorage.WriteAtomic`/`Delete` (`Orpheus.Save.HostLockFile`), а не в `world.lock`: тот держится без совместного доступа, прочитать его другой процесс не может. Живость — по `world.lock` (`TryLock` на миг): после пропажи света `host.lock` остаётся, но мир никто не держит → `FindRunning` = null. Удаляется при штатном выходе до того, как отпущен `world.lock`.
- **Ключи сервера:** `--mode single|host --host-token <32 hex> [--open-address all|IPv4] [--open-port P] [--host-grace сек]`; режим требует `--port`, `--world`, токен; с `--public` нельзя. Вход с токеном → флаг «хозяин»; токен неверный или у сервера хозяина нет → отказ `BadToken`. Вход с тем же токеном вытесняет висящее соединение упавшей игры (7.7, `Closing.Replaced`). Штатная остановка игрой — строка `stop` в stdin (конец stdin — не команда: игра упала).
- **«Открыть для друзей»** `[док]` — сообщение протокола от хозяина (`OpenForFriends` → `OpenResult`), второй слушающий `LiteNetTransport` добавляется в `MuxTransport` под тем же `NetServer`: петля не трогается, такт не прерывается. Протокол — версия 3 (токен во входе +1…17 байт, типы 8–10). Адрес по умолчанию — все (IPv4 Any + IPv6 Any, как `--public`), тесты — 127.0.0.2 (`IPv6Enabled = false`), LiteNetLib с ним работает, клиент на 127.0.0.1 ходит к 127.0.0.2.
- **Падения:** хозяин ушёл → `HostSession` ждёт `--host-grace` (60 с) **от последнего сообщения хозяина** (транспорт замечает убитую игру лишь через тайм-аут 10 с); других игроков нет — сразу фоновое сохранение (`WorldSaver.SaveNow`). Срок вышел → «хост вышел»: сохранение при остановке, всем отключение с `Closing.HostLeft`, выход с кодом 0. Хозяин так и не вошёл — тот же срок от старта `[док]`. Клиент: `NetClient.DisconnectText` — текст по причине или «Связь с хостом потеряна» по обрыву `[док]`; «Мир остановился…» у игры хоста — шаг 6.
- Вывод сервера в закрытую трубу (игра упала) не роняет сервер: `JsonLog` ловит `IOException` консоли и пишет дальше только в файл. Проверено тестами с убийством процесса игры.
- Боты — «игра хоста» без Unity: `--launch <OrpheusServer> --world … [--create-seed N] [--mode] [--open-address] [--open-port] [--host-grace] [--server-arg …]`, `--find <папка>`, `--host-token`, `--open-for-friends`; в отчёте `serverPid`, `serverReadySeconds`, `openedPort`, `disconnectText`.
- Тесты с 60-с ожиданием и убийством процессов — `Category=Big` (ночной `-All`); в быстром CI — связь в памяти, `ServerRun` в процессе теста с ожиданием 1 с и один тест лаунчера с UDP (3–4 с).
- Вопросы `[док]` карточки — допущения выше и строки в `work/backlog.md`; пауза по Esc, UPnP, офлайн-режим клиента — не делались.
- **Клиент Unity (шаг 6, К):** ключи `ClientArgs` — `--single` / `--host` (режим сервера; меню — заглушка), `--world <папка>` (по умолчанию `persistentDataPath/Worlds/world-1`; нет `world.base` — создать по `--seed`/`--size`), `--server <путь>` (по умолчанию `PcServerLauncher.DefaultPath(папка Orpheus.exe)`), `--server-arg A` (повторяемый, например боты для net-smoke), `--open-for-friends` (сразу после входа; в игре — клавиша **F2**, заглушка меню), `--open-address IPv4` и `--open-port P` (прогоны — только 127.0.0.2; «все адреса» ключом не задаётся — это умолчание игры). С `--connect` вместе нельзя; `--net-smoke` — с `--connect`, `--single` или `--host`.
- `LocalServer` (`client/Assets/Scripts`): сначала `FindRunning` по `host.lock` (игра вернулась после падения — вход с токеном из замка, ничего не запускается), иначе `PcServerLauncher.Start` в фоновой задаче — кадры не стоят, «Запуск мира…» в окне. `Process` клиент сам не трогает (тест 1.6 зелёный). Жив ли сервер: свой — `HasExited` каждый кадр, найденный по замку — `FindRunning` раз в 1 с. Упал — «Мир остановился. Последнее сохранение — N мин назад (меньше минуты / нет). Запустите игру снова, чтобы загрузить его» `[док]`: время — по новейшему `world.N.save` или `world.base`; «загрузить» — перезапуском игры, пока нет меню. Обрыв и закрытие мира — `NetClient.DisconnectText` («Хост вышел…», «Связь с хостом потеряна»).
- Выход игры — `IServerInstance.Stop` (строка `stop`, ожидание до 10 с, затем снять): сервер сохраняет и выходит с кодом 0; net-smoke своего сервера красный, если код не 0. Найденный по замку сервер игрой не останавливается (его stdin у упавшей игры) — закроет мир сам через 60 с без хозяина (7.6) `[док]`.
- `build_client.ps1` после сборки Unity делает `dotnet publish src/Orpheus.Server -o build/client-win` (зависит от рантайма .NET 9, как сервер для `playable`; самодостаточная сборка — с установщиком) и с ключом `-HostSmoke` гоняет net-smoke хоста; сервер, переживший клиента, снимается по номеру и прогон красный.
