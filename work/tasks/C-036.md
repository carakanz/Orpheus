# C-036: видимость чужих действий — взмах кирки и натяжение лука в снимке

Ветка `task/C-036`, копия `.claude/worktrees/tc036`, база `main 2fa549c`.

## Цель
Чужие игроки видны **копающими** (взмах кирки по C-028) и **натягивающими лук** (E3-2):
1. В снимке — новое поле «действие» персонажа: инструмент (кирка/лук) + фаза/прогресс.
2. Клиент `NetAnimation.Remote` рисует чужой замах кирки и чужое натяжение лука
   (у меча уже есть: `SnapshotEntity.Melee` → `RemoteSwing`).

Протокол: **37** (следующий после C-035 = 36). Сохранение (16) не трогается.

## План
1. Поле `Action` (byte) в `SnapshotEntity`: 0 — покой; инструмент 2 бита (1 — кирка, 2 — лук),
   прогресс 6 бит (кирка: кадр замаха из окна взмаха; лук: сила `PowerQ8>>2`… точную раскладку
   зафиксировать в коде и тестах голденами). Только для персонажей; враги — 0.
2. Сервер: заполнение из bow-фазы (`Bow.Phase != 0` → лук, прогресс `ShotDraw`/`FullDrawFrames`)
   и окна взмаха кирки (копание игрока: прогресс от начала взмаха); дельта-бит 64 в
   `NetServer.Snapshots.cs` (сравнение + `TryAdd`/`TryAddUpdated`/`TryAddAdded`).
3. Клиент: `NetAnimation.Remote` — по `Action`: замах кирки (поза как у меча, инструмент — кирка),
   натяжение лука (`DrawPower` из прогресса, «внатяг» пока фаза активна, конец — выстрел-отдача).
4. Голден-байты снимка с новым полем; тесты: дельта приходит при смене фазы и только тогда;
   копка чужого видна в снимке (rig: копает A, B видит `Action` A); лук чужого (натяжение →
   полный → 0); свои анимации не меняются.
5. Снимки экрана (`tools/shots.ps1`, скрытый стол): два клиента — один копает скалу, второй
   тянет лук; кадры: замах, натуга, полный пролёт.

## Решения
- Раскладка `Action` (8 бит): инструмент — младшие 2 бита (0 покой, 1 кирка, 2 лук),
  прогресс — 6 бит (`ActionProgressShift=2`, маска `0x3F`); `EncodeAction` клампит
  прогресс 0…63. Дельта-бит `DeltaFields.Action = 64`, `MaskBits` 6→7, `ActionBits=8`.
- Кирка: прогресс = `ceil(DigProgress / 16)` — квант `SnapshotLayout.ActionDigQuantum = 16`
  (~0,27 с на шаг; вынесен в layout — клиент считает длину замаха чужого по тому же кванту).
  Дельта — раз в окно, не каждый такт. Взмах 24 кадра → шаги 1, 2.
- Лук: только `Bow.Phase == PhaseDraw`, прогресс = `PowerQ8(Frames) >> 2` (0…63; Q8 256 →
  64 → клампинг 63). На полном натяжении выстрел в тот же кадр — снимок успевает увидеть
  ~58 (проверка `InRange 56…63`). Отход (`PhaseRecover`) — 0: отдачу клиент рисует по
  сообщению снаряда (E3-2). Зажатая ЛКМ — непрерывная стрельба (C-031): тест отпускает
  на 36-м кадре, иначе сегмент натяжения возобновляется.
- Клиент `NetAnimation.RemoteAction`: кирка — замах по шагам (окно = шаг × квант,
  `ActionSec`/`ActionFrames` для `BeatPhase`); лук — `DrawPower = step/63`, `DrawSec` из
  обратного `PowerQ8`; ось — взгляд (`FacingRight`, прицела чужого в снимке нет). Словарь
  чистится в `ForgetGoneMelee` (счётчик `RemoteActionTracked`).
- Протокол 36 → **37** (9 тестовых assert'ов подняты). Сейв 16 не трогается.
  Голдены `D07_S2_10_GoldenBytes_AllMessages` обновлены (снимок 48 байт, дельта 50) +
  assert'ы Action (round-trip, дельта-бит, added).
- [док] Позы клиента (`NetAnimation.RemoteAction`, `AnimShowcase.Action.cs`) dotnet-тестами
  **не проверяются**: `Orpheus.Tests.csproj` компилирует из клиента только `Anim/Pose/*.cs`
  (прошлая запись о parity-тесте была ложной — тестов в `C036ActionTests` ровно 3). Проверка
  клиента по конструкции проекта: smoke-сборка (код 0) + витрина + снятые ленты C-036_pick /
  C-036_bow (просмотрены исполнителем, формулы сверены глазами с `RemoteAction`). Тестовая
  обвязка клиентских поз — отдельная задача (backlog).
- [док] `--anim-shots` перегенерирует **всю** витрину: в `51498d4` обновлены 28 существующих
  снимков и добавлены отсутствовавшие `E2-7_*` — принято (кадры детерминированы, снимки свежие
  с HEAD).

  и в сообщении коммита `51498d4` сказано, что parity-тест «Витрина ↔ RemoteAction (паритет)» есть в
  `C036ActionTests.cs` — **его там нет**: в файле ровно 3 теста (`C036_Codec_Action_EncodeDecode_Clamps`,
  `C036_Net_DigPick_ObserverSeesSteps_RestingZero`, `C036_Net_BowDraw_ObserverSeesPower_ThenZero`); grep по
  `tests/` на `паритет|parity|RemoteAction|AnimShowcase|CompareShowcase` даёт только `CombatTests.cs` (не про то).
  То есть H2 первой проверки **не снят**, а закрыт по ложному основанию.
- **H2 (покрытие): клиентская часть карточки тестом не покрыта.** `NetAnimation.cs` не компилируется в тестовую
  сборку (`tests/Orpheus.Tests/Orpheus.Tests.csproj` берёт из клиента только `Anim/Pose/*.cs`), поэтому М-П3
  выживает: удаление натяжения лука у наблюдателя не детектируется ничем, кроме smoke-сборки и снимков.
  Завести parity-тест (формулы витрины ↔ `RemoteAction`) — отдельной карточкой, как в других витринах.
- **M1 (чужая область): коммит `51498d4` перезаписал 28 чужих снимков** (`C-012_*`, `C-028_*`, `C-031_*`,
  `E3-2_*`, `E3-3_*`, `E3-4_*`, `K-001_*`) и добавил `E2-7_*` — `--anim-shots` перегенерил всю витрину.
  Для карточки нужны были два файла. Доказательства предыдущих карточек заменены новыми кадрами; в «Решения»
  это не записано. Впредь — ограничивать вывод `--anim-shots` именами своей ленты.
- **L1:** `ActionOf` в ветке кирки не проверяет смерть: мертвый игрок продолжает копать (сервер), пока клиент
  держит клавишу, — `DropDig` только при `slot < 0` (`NetServer.Input.cs:242`, `NetServer.Edits.cs:103`),
  `Action` ≠ 0 до конца окна. Поведение унаследовано от C-028 (зеркалится), в `Action` нового не добавлено.
- **L2:** `EncodeAction` не маскирует инструмент (значение 3+ протечёт в биты прогресса); сервер и тесты
  передают только 0/1/2, на проводе инструмент 3 запрещён тестом. При расширении инструментария — замаскировать.
- **L3:** враг с луком дал бы `Action ≠ 0`; сейчас ИИ лук не натягивает (гейт `Simulation.Projectiles.cs:196
  BowInputOf`), поэтому «враги — 0» выполняется фактически, а не по коду `ActionOf`.
- **Автору:** визуальная приёмка лент `work/screens/C-036_pick.png` (1,59 МБ) и `C-036_bow.png` (2,03 МБ) —
  за Автором; файлы в репозитории, кадры просмотрены исполнителем.
