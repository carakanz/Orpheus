# E2-2 — быстрая панель и окно сумки (план, шаг 2.2)

## Цель
В игре есть быстрая панель и окно сумки: перенос, деление стопки, выброс; снимки окон; тест перекладывает предметы через тот же путь, что игрок.

1. Каркас UI в `client/Assets/Scripts/UI/` (холст, стиль, окно, сетка ячеек, значок, подсказка, «рука»).
2. Быстрая панель: 8 ячеек, значки, числа, рамка выбранной; 1–8, Alt + колесо.
3. Окно сумки (Tab): сетка 8 × 5, ЛКМ / ПКМ / Shift+ЛКМ / выброс; подсказка; заявки серверу (29).
4. Полосы здоровья и выносливости без `--hud`.
5. Значки всех предметов таблицы (`tools/make_item_icons.py`).
6. Общий класс заявок `BagHand` (Orpheus.Net) — им пользуются окно и тест по сети.
7. Сцены стенда `--ui-demo bag|hotbar`, снимки 1920 × 1080 и 1280 × 720.
8. Сборка `-Smoke -HostSmoke`, быстрый CI, журналы модулей.

## Решения (приняты без Автора)
- **Способ UI — uGUI, всё создаётся кодом** (без сцен и префабов). Холст — в мировом пространстве перед основной камерой (`RenderMode.WorldSpace`), подгоняется под кадр каждый кадр и перед снимком: размер холста 1080 единиц по высоте (эталон 1080), ширина по соотношению сторон. Причина: снимок стенда рисуется камерой в текстуру другого размера, чем окно (окно стенда 320 × 180) — режим Overlay в текстуру не попадает, а Screen Space - Camera берёт масштаб от окна и даёт мутный текст. Порядок отрисовки холста — выше слоя тона суток (ночь интерфейс не красит).
- **Мышь по интерфейсу — своя проверка попадания** (прямоугольники в координатах холста), без EventSystem: одно место ввода (`GameUi.Frame`), тот же код работает на стенде снимков со «скриптовым» курсором.
- **Шрифт — временно динамический шрифт ОС** (`Font.CreateDynamicFontFromOSFont`: Segoe UI → Arial → Tahoma; запасной — встроенный `LegacyRuntime.ttf`, им рисуется отладочная строка, кириллица у него тоже берётся из шрифтов ОС). Свободного шрифта с OFL на машине в репозитории нет, из сети не качаем, системные в репозиторий не копируем. Заменить на свой файл шрифта в `client/Assets/Fonts/` — в «Дальше» `ui.md`.
- **«Рука» — только на клиенте.** У сервера нет ячейки курсора: взятая стопка остаётся в своей ячейке, окно лишь показывает её у курсора и уменьшает число в ячейке. Заявка уходит в момент «положить»: целая стопка — `Move` (перенос / доукладка / обмен решает сервер), часть — `Split`, вне окна — `Drop`.
- **Ответа ждём, не предсказываем**: после заявки рука пуста, ячейки показывают сумку сервера (сообщение 26 приходит ≤ 200 мс). Отказ сервера = сумка не изменилась — окно и так показывает состояние сервера.
- ПКМ по стопке — взять половину (с округлением вверх); ПКМ с предметом в руке — вернуть (отмена). Закрытие окна с предметом в руке — отмена.
- Shift+ЛКМ: цель выбирает клиент — первая ячейка другой области (панель ↔ сумка) с тем же предметом и местом, иначе первая пустая; уходит обычная `Move`.
- Деление в стопку того же предмета: клиент просит не больше, чем влезает (сервер `Split` принимает только «влезает целиком»).
- Мёртвый: окно открывается, но рука не берёт и заявки не шлются.
- Общий класс `BagHand` лежит в `src/Orpheus.Net/Session/` (новый файл; `NetClient` получил интерфейс `IBagRequests` отдельным partial-файлом) — единственная правка сети; протокол не менялся.
