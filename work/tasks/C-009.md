# C-009 — хвосты тестов пути (проверка шага 2.12b)

**Модуль-владелец:** `combat` (путь врагов, погоня). **Ветка:** `task/C-009`. **Источник:** замечания 1–5 проверки (П) `E2-12b.md`, 15.11. Код менять, только если тест вскроет дефект.

## Что сделать

1. Тест «застрявший враг ищет путь заново»: флаг «без подруливания» только для тестов (internal, по умолчанию выключен, не в протоколе/сохранении); враг упирается в косяк/угол, за ≤ 180 тактов новый путь и продвижение. Мутация «застрял — кэш до правки мира» — красный.
2. Тест на уход цели (`BlockedGoalMoved`): цель в замкнутой области выходит наружу — враг ищет заново и идёт к ней.
3. Тест подруливания у диагонального хода (мутация «нет подруливания у диагонали» выжила).
4. Раскачка у косяка: продвижение ≥ 0,19 т сбрасывало таймер сдачи — тест; подтвердится — исправить (сброс только приближением к цели).
5. `D02_S8_13_RogueStrikes_Dodged95of100`: проверка доли начатых рывков.

## Решения

- **Флаги для тестов** (`Simulation.Steer.cs`, `internal`, `InternalsVisibleTo Orpheus.Tests` в `Orpheus.Core.csproj`): `SteerOffForTests` (подруливание выключено), `PlaceForTests` (перенос сущности — модель толкотни/отбрасывания и «игрок вышел из дома»), `TouchesSolidForTests`; `SteerTo`/`Closer` — `internal`. В протокол, сохранение и хэш не входят.
- **Задача 1 — сценарий.** Без подруливания враг, подходящий к проёму наискосок, у косяка стоит и после переспроса: путь из точки упора тот же, первый ход снова в угол — сдаётся через 20 с (так и должно быть). Поэтому «переспрос спасает» проверен там, где старый путь протух: враг шёл в проём, толкотня (перенос) сбила его внутрь комнаты к западной стене; следующая точка старого пути — снаружи прямо на запад, ход упирается в стену. Фаза «путь старый» (150 тактов) выбрана так, чтобы сама не спасала.
- **Задача 3 — мутация эквивалентна, ветка удалена.** Столкновения по осям (X, потом Y) не откатывают за старт: диагональ не приближает, только если оба осевых сдвига нулевые, — тогда и чисто осевые шаги стоят. Перебор: 871 тыс. случаев (точки дальше прохода 1/4 т, ячейки и целые тайлы) — диагональ упёрлась 295 раз, ось помогла бы 0. Ветка `SteerTo` для диагонали (оси) удалена — поведение не меняется (пути и хэши те же). Тест `C009_Steer_DiagonalBlocked_AxesBlockedToo` держит свойство: изменятся столкновения — красный, ветку вернуть. Ближе 64 ед. (точка уже «пройдена») ось иногда помогает из‑за перелёта — FollowPath туда не ведёт.
- **Задача 4 — дефект подтверждён, исправлен.** Враг у косяка, которого толкотня отбрасывает на 0,4 т каждые 40 тактов, возвращается — смещение ≥ 0,19 т закрывало эпизод «упёрся» (`BlockedSince = 0`), а сдача проверялась только в Blocked, куда он не доходил: не сдавался никогда (тест красный на обоих звеньях, мутации M3, M4). Теперь: (а) в эпизоде (`BlockedSince ≠ 0`) контрольная точка продвижения — ближайшее к цели место эпизода; переезжает и закрывает эпизод только приближение к цели по прямой на ≥ 48 ед. (`CloserToTarget`, до текущей позиции цели — идущий за уходящей целью враг ближе к ней, чем точка позади); смещение вбок/назад сбрасывает только таймер «застрял»; (б) сдача через 20 с эпизода проверяется и в погоне, не только в Blocked. Вне эпизода — как было. Новых полей нет (сохранение не меняется). Цена: обход, начатый в эпизоде, без приближения к цели по прямой дольше 20 с — сдача (раньше крутился бы бесконечно); в тестах леса, случаев Автора, проёмов — не встречается.
- **Задача 5 — порог 60 %, а не 90 %** `[док]`: правило выносливости (рывок −25, пауза 0,5 с, +20/с) при замахе раз в 1,1 с даёт в установившемся режиме долю рывков f из 25f = 12f + 22(1 − f), f = 22/35 ≈ 63 % (+ начальный запас); замер 110 из 160. Главная защита — вторая проверка: каждое нажатие при выносливости ≥ 25 и готовом увороте начинает рывок (100 %). Мутация «рывок только при выносливости ≥ 75» — старые проверки зелёные (выборка добрана), новая красная (172 нажатия, 110 рывков).
- Задача 2: при ходьбе игрока по дому 3 тайла — 1 поиск (переспрос при уходе цели дальше тайла).
