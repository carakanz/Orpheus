# E3-1 (шаг 3.1) — урон цифрами, смерть и возрождение на экране

Модули: `ui`, `actors`, `combat` (события). Ветка `task/E3-1`, копия `.claude/worktrees/te31`. План — `work/PLAN.md` этап 3, шаг 3.1 («полосы здоровья и выносливости, урон цифрами, смерть и возрождение на экране», готово: С — снимки). Шары здоровья/выносливости уже есть (C-015).

## Что сделать
1. **Урон цифрами:** над существом, получившим урон, всплывает число (красное — урон игроку, белое/жёлтое — урон врагу, зелёное — лечение/самовосстановление постройки не показывать), летит вверх и тает за ~0,8 с, крит/сильный удар — крупнее. Свой и чужой урон — из снимка/событий сервера (не из предсказания — чтобы не было ложных цифр); если события урона в протоколе нет — добавить (следующий номер протокола).
2. **Полоска здоровья врага** над головой, видна после первого попадания и 4 с после последнего; у элитных/боссов — всегда, с именем.
3. **Смерть игрока:** экран темнеет, надпись «Вы погибли», причина (кто убил), таймер возрождения (сколько по правилам ядра), кнопка/клавиша «Возродиться» когда можно; возрождение — у кровати, иначе у Очага (правило уже в ядре — проверить). Выпавшие вещи (если по правилам выпадают) — метка на карте/мини-карте.
4. **Смерть врага:** анимация падения/растворения (процедурная, `Anim/`), без мгновенного исчезновения.
5. Все размеры — `HudLayout`, рисование — чётко (шейдер `UiShape`, текст на целых пикселях, как C-015).

## Готово, когда
- Снимки (скрытый стол, монитор 2): цифры урона по врагу и по игроку, полоска врага, экран смерти, возрождение → `work/screens/E3-1_*.png`, исполнитель сам смотрит каждую.

## Проверка (П)

**Итог: принять.** Проверено на `178e352` (дифф `main...origin/task/E3-1`), тесты `E31*` — 10/10 зелёные; тяжёлые тесты и игра с графикой не запускались (по заданию), CI и D08_3_1 — по отчёту исполнителя.

**Протокол 30.**
- 37 «урон»: получатели — жертва, атакующий и игроки в 56 тайлах от жертвы по каждой оси; расстояние — `Torus.Delta` (шов учтён; мутация «вычитание вместо `Torus.Delta`» не собирается — анализатор ORP001). Далёкий игрок (200 тайлов) не получает ничего — тест.
- Дублей нет: решение угрозы (`Decide`) идёт в разборе ввода до `Step`, а `Step` обнуляет буфер событий — событие вне такта не уходит второй раз из `BroadcastCombatEvents`; тест «ровно раз, в порядке сервера» и `DamageMessagesSent = 2 × событий` это держат. Урон и смерть одного удара идут по одному надёжному каналу (Facts) в порядке «урон → смерть» (в такте — порядок событий, в `Decide` — `BroadcastDamage` до `BroadcastDeath`).
- Объём: 13 байт × получателей на каждое событие урона, без ограничения частоты. При 8 игроках рядом и толпе врагов — порядка 10–30 сообщений урона на игрока за такт в худшем случае (сотни байт/такт), это заметно меньше снимков; потолок даёт размер буфера событий ядра. Приемлемо для среза; если в E3-x появятся АоЕ/яды по тикам — склеивать в одно сообщение на такт.
- Совместимость: версия 30, вход с другой версией отклоняется (`VersionMismatch`); золотые байты 37 и 24 закреплены; отказ на урон 0 и чужие флаги.

**Ядро.** Правила боя не менялись: `ApplyStrike` получил необязательный `strong`, он пишется только в `SimEvent.Tag` (событие в хэш состояния не входит — сущности и их поля не менялись). «Сильный» — только добивающий удар серии (`m.Index == SeriesSize − 1`), тест 10/10/13/10. `RespawnsAtBed` — только чтение, повторяет условие `RespawnPointOf`. Детерминизм — тест двух прогонов.

**Клиент.** Цифры рисуются только из `DamageSeen` (37) через `CombatFeed`; предсказание их не порождает. Таймер смерти — из `RespawnTicks` сообщения. Сброс экрана смерти — по своему «возрождению» (25); мутация «не сбрасывать `Dead`» — красная.

**Мутации (мои).**
1. `Torus.Delta` → простое вычитание в радиусе рассылки — не собирается (ORP001): шов защищён анализатором, тестом — нет.
2. Обход проверки расстояния для жертвы/атакующего убран (`if (true)`) — **тесты зелёные**: в сцене атакующий всегда рядом с жертвой. Сейчас не важно (ближний бой), но для лука E3-2 атакующий может быть дальше 56 тайлов — стоит добавить случай в тест там.
3. `CombatFeed.OnRespawn` не сбрасывает `Dead` — красный.

**Старые тесты 29→30.** Только номер версии и граница известных типов (`IsKnown(37)` → `IsKnown(38)`, последний тип `NearbyStock` → `Damage`) — не ослаблены; `IsKnown(37) == true` проверяет новый золотой тест.

**Замечания (не блокируют).**
- Переподключение во время смерти: новое подключение не получает уже разосланную «смерть» — экрана смерти не будет до возрождения (персонаж лежит по снимку). Редкий случай; при желании — смерть/оставшиеся такты во «входе принят» или в своём состоянии снимка.
- «У кровати» вычисляется в миг смерти; если кровать снесут за 5 с ожидания, надпись после возрождения («у кровати») будет неверной — `RespawnMessage` места не несёт. Мелочь.
