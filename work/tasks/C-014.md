# C-014 — дверь закрывается через 0,5 с после того, как её хитбокс пуст

Модули: `building`, `sim`. Ветка `task/C-014`, копия `.claude/worktrees/tc014`. Слово Автора 15.11 (приёмка), дословно:
> Двери должны быстрее закрываться. Сразу через пол секунды как в их хитбоксе никого нет

## Сейчас
`Simulation.DoorAutoCloseTicks = 30` (1 с), условие — `TileAndNeighborsFree(tile)`: свободны тайл двери **и соседи** (`Simulation.Doors.cs`, `StepDoors`). Из-за соседей дверь держится открытой, пока кто-то стоит рядом, а не в проёме.

## Что сделать
1. Задержка 0,5 с = 15 тактов (`DoorAutoCloseTicks`).
2. Условие «пусто» — по **хитбоксу двери**: клетки, которые дверь занимает (с тонкими дверями 2.12/2.17 — её полоса/половины на сетке 0,5, а не весь тайл с соседями). Никто (игрок, враг) не пересекает этот прямоугольник — таймер идёт; пересёк — таймер снимается.
3. Закрытие не должно защемлять: если в миг закрытия в хитбоксе кто-то есть — не закрывать (выталкивание `BeginDoorClose` остаётся страховкой).
4. Таймер и сохранение — как было (дедлайн в записи); проверить, что не конфликтует с очередью урона/обломков E2-14 (поле `DebrisEndTick` у двери).
5. Обновить тесты 1-012/дверей (ожидания 30 → 15, «сосед рядом — дверь закрывается»), golden при необходимости; `work/modules/building.md` — правило `[док]` (в `docs/` было 1 с — расхождение записать в `work/backlog.md`).

## Готово, когда
- Тесты: проход сквозь дверь → закрыта через 15 тактов после выхода из хитбокса; стоит вплотную сбоку вне хитбокса — закрывается; стоит в проёме — открыта. Быстрый CI зелёный (кроме `work/flaky.md`); D08_3_1 — один раз (боты ходят через двери); сборка `-Smoke -HostSmoke` код 0.

## Отчёт исполнителя
**Сделано** (`src/Orpheus.Core/Sim/Simulation.Doors.cs`, `Simulation.cs`, `Simulation.Edits.cs`):
- `DoorAutoCloseTicks` 30 → 15 (0,5 с).
- «Пусто» — `DoorHitboxFree`: ни одно живое существо (игрок, враг) не пересекает **ячейки двери** (`DoorCells` = `BuildCells.MaskOf`: тонкая дверь — пара ячеек 0,5; старые миры без маски — весь тайл). `TileAndNeighborsFree` (тайл + соседи) удалён.
- Защемления нет: на такте дедлайна проверка хитбокса идёт до `BeginDoorClose`; занят — таймер снимается. В `BeginDoorClose` (авто и F) отказ «персонаж в проёме» и выталкивание врага — тоже по ячейкам двери, иначе стоящий во второй половине тайла держал бы дверь вечно; правка закрытия по-прежнему проверяет существ по ячейкам (`RequestPlayerEdit`).
- Открытие: страховка «в проёме» — по ячейкам; шаг к двери открывает из соседнего тайла **и из её тайла вне ячеек** (иначе из северной половины тонкой двери в неё не войти), направление — к центру хитбокса (`DoorHitboxCenter`; у двери на весь тайл — центр тайла, как было). Стоящий рядом без ввода дверь не открывает — «открыть — закрыть» по кругу нет (тест).
- Таймер и сохранение — как было: дедлайн в `DebrisEndTick` записи двери. С E2-14 не конфликтует: очередь обломков/флагов — `_expire` (`Simulation.Expiry.cs`), поле записи не читает; обломки — другой объект; восстановление прочности вливается в дверную правку того же такта (E2-14).

**Решения**
- `[док]` Хитбокс считается для всех живых, включая врагов (как раньше `TileAndNeighborsFree`; в карточке «никто (игрок, враг)»). `docs/05` 1.3 / `02` 9.3 («1 с, тайл и соседи, без врагов») — строка `[док]` в `work/backlog.md`.
- F-закрытие теперь тоже разрешено, если персонаж в другой половине тайла (вне ячеек) — то же правило проёма.
- Известно, не менялось: дедлайн `tickMod + 15 == 0` (раз в 65 536 тактов) значит «не заведён» — закрытие сдвигается на 1 такт.

**Тесты:** `C014DoorTests` (6): проход сквозь тонкую дверь — закрыта ровно через 15 тактов после выхода круга из ячеек; стоит в той же клетке вне ячеек — закрывается ≤ 16 и не открывается снова 60 тактов; шаг из своего тайла открывает закрытую; игрок / враг в проёме — открыта 60 тактов; край хитбокса точен (касание без пересечения — закрывается, на 1 unit глубже — нет). `DoorTests.D12_Stays_Open_While_Player_Neighbor` → `D12_Closes_While_Player_Neighbor_Outside_Hitbox`; `D12_F_On_Closed_Door_Extends_Lock` — проверка «открылась шагом» по факту открытия в цикле (дверь за прошедшим теперь закрывается за 15 тактов до конца цикла). Мутации (все убиты): 15→16, 15→30, хитбокс = весь тайл, открытие только с соседнего тайла, страховка по всему тайлу, таймер не снимается при входе, `BeginDoorClose` по всему тайлу. Golden не менялись.

**Прогоны:** быстрый CI — 1087/1095, упали 7 из `work/flaky.md` (одиночно зелёные) и `Pause15s` (одиночно 2 из 10 красных, на базе e16652b 0 из 9; плоский мир без дверей — записан в `flaky.md`). D08_3_1 (6 тестов, боты ходят через двери) — зелёный, 13 мин 24 с. Сборка `toolsuild_client.ps1 -Backend Mono -Smoke -HostSmoke` — код 0 (113 с): тайлов 0 расхождений, host-smoke код 0.

**Не проверено (ждёт снимков):** визуально — нет (снимки запрещены 15.11); картинки дверей карточка не меняет.

## Проверка (П)
**Итог: принять.** Проверено по `git diff main...origin/task/C-014` (3 коммита), рабочая копия `tc014`.

1. **Хитбокс.** `DoorCells` = `BuildCells.MaskOf` — для всех четырёх ориентаций берётся маска записи (`DoorNorth/South/West/East`), у старых миров (Cells = 0) и двери без записи — весь тайл. Радиус у всех существ один (`Collision.RadiusUnits`, врагов «больше» нет), проверка та же, что у движения (`OverlapsTile` по маске), поэтому закрытие при пустом хитбоксе не защемляет; между `StepDoors` и `ApplyEditBatches` движения нет (фазы 4.5 → 5 одного такта), так что за этот промежуток никто в ячейки не войдёт. Выталкивание врага в `BeginDoorClose` — по ячейкам, цель — соседний тайл, как было. Временным тестом (не закоммичен) прогнал все 4 ориентации тонкой двери: враг в ячейках — открыта 60 тактов; игрок во второй половине тайла — закрылась ≤ 16 и не открылась снова 60 тактов; шаг к двери из второй половины — открыл и прошёл.
