# Продюсер — как вести работу (читать в начале каждой сессии)

Короткая инструкция для любой основной сессии (Claude Code, opencode с локальной моделью — всё равно). Полные правила — `docs/08_roadmap.md`, раздел 7; здесь — то, что нарушалось и чего нельзя нарушать.

## Старт сессии — читать только это

1. `work/PRODUCER.md` (этот файл).
2. `work/next.md` — очередь: что делать сейчас, по порядку.
3. `work/status.md` — последние 10 строк.
4. Карточку задачи, которую берёшь (`work/tasks/<веха>-<NNN>.md`), и только те разделы документов, на которые она ссылается.

Не читать целиком `docs/*.md`, историю чатов, все карточки подряд: контекст 128K кончается, сжатие истории ломается, работа теряется. Если контекст заполнен больше чем наполовину — допиши «место остановки» в карточку, закоммить, остановись.

## Жёсткие правила

1. **Без карточки нет работы.** Новая задача → сначала карточка в `work/tasks/` (цель, ссылки, шаги, чек-лист, «не трогать»), коммит карточки в `main`, потом код.
2. **Код — только в ветке и отдельной рабочей копии.** `git worktree add -b task/<веха>-<NNN> .claude/worktrees/t<NNN> main`. В основной папке `C:\Users\carak\source\Orpheus` на ветке `main` код не правится — только журнал (`work/status.md`, `work/next.md`, `work/backlog.md`) и карточки. Исполнитель и проверяющий пишут файлы **только по абсолютным путям внутри своей рабочей копии** и не делают `cd` в основную папку: относительный путь или не та рабочая папка уже дважды оставляли чужие правки в основной (07.11).
3. **Исполнитель не принимает свою работу.** Проверка (П) — отдельная сессия или подагент с чистым контекстом: читает карточку и дифф, гоняет CI, делает 1–2 мутации, пишет в конец карточки `## Проверка (П)` с итогом. Без этого раздела с «принято» — **не сливать**, и в журнале не писать «принята П».
4. **В `main` — только зелёное.** Перед слиянием: `cmd /c tools\ci.cmd` в ветке зелёный; после слияния — ещё раз в `main`. Красный `main` — чинить раньше всего остального.
5. **Коммиты.** Сообщение по-русски, кириллицей (не транслитом), через файл: `git commit -F msg.txt` — файл в UTF-8 **без BOM** (в PowerShell 5.1: `[IO.File]::WriteAllText(путь, текст, (New-Object Text.UTF8Encoding $false))`). Последняя строка — `Co-Authored-By: ...` своей модели. WIP-коммит не реже раза в 30 мин и сразу `git push`.
6. **Порядок — по `work/next.md`,** а не «что интереснее». Долг проверки — раньше новых задач.
7. **Документы — источник правды.** Код расходится с `docs/` — вопрос в `work/backlog.md` с пометкой `[док]`, а не тихая правка документа или кода. `docs/` правит только комната дизайна.
8. **Временные ассеты** — по `CLAUDE.md` (папка `_TEMP`, префикс `TEMP_`, `art/manifest.csv`, пурпурный уголок).
9. **Unity** — пакетный режим; не больше одного процесса Unity на проект; Unity Hub и `Unity.Licensing.Client.exe` не убивать.
10. **Статус** — одна строка в `work/status.md` на событие: задача, итог, ключевое число, коммит. Не писать того, чего не было («принята П» без раздела проверки).

## Цикл задачи

карточка → рабочая копия и ветка → шаги с WIP-коммитами → чек-лист и замер в карточке → **проверка отдельным агентом** → правки → повторная проверка → слияние `--no-ff` в `main` → CI в `main` → push → строка в `status.md` → вычеркнуть в `next.md` → убрать рабочую копию.
