# Переезд на C++ и Unreal Engine 5 — план (08.11.2026)

**Решение Автора** (`BRIEF.md` п. 2a): игра — полноценное 3D с камерой сверху под углом, как Diablo / Path of Exile (по стилю — Torchlight), на **Unreal Engine 5**; **весь код — на C++** («Давай всё на C++»). Стиль Б (контур + плоская заливка) — мультяшным шейдером с обводкой.

Что остаётся неизменным: дизайн игры (`docs/`), правила сети и мира (тор, чанки 32², тайлы, такт 30 Гц, целые координаты 1/256 тайла, снимки и дельты, предсказание, опережение L, сохранения с атомарной записью), процесс (карточки, ветки, независимая проверка, CI). Меняются язык, движок клиента и отрисовка.

## Архитектура (предложение Продюсера; документы правит комната дизайна)

| Слой | Было (C#) | Будет (C++) | Почему так |
|---|---|---|---|
| **Ядро** (тор, чанки, мир, движение, уворот, путь, сим, правки) | `Orpheus.Core` netstandard2.1 | **библиотека C++20 без зависимостей от Unreal** (`core/`), CMake | один и тот же код у сервера и клиента — предсказание без правок держится на побитовом совпадении; без Unreal — быстрые тесты и сервер без движка |
| **Сеть** (протокол, снимки, дельты, часы, чанки) | `Orpheus.Net` + LiteNetLib | **своя библиотека C++** (`net/`) поверх **ENet** (надёжный/ненадёжный UDP, каналы; C, переносим, на консолях используется) за интерфейсом транспорта | своя схема сети не ложится на репликацию Unreal (тор, плавающее начало, свои снимки) — оставляем свою, как в `07`; интерфейс транспорта — чтобы на PS5 подставить платформенный |
| **Сохранения** | `Orpheus.Save`, `Orpheus.Platform.Pc` | `save/` + платформенный слой (Windows/Linux: `FlushFileBuffers`/`fsync`, атомарный перенос) | у Автора нет ИБП — та же гарантия записи |
| **Сервер** | `OrpheusServer` (.NET 9) | **отдельный консольный exe C++** (Windows и Linux — выделенный сервер на Debian) на ядре и сети, **без Unreal** | маленький, быстрый, без движка; одиночная и хост — дочерним процессом (как 0-024), на PS5 — в потоке клиента (ядро без Unreal это позволяет) |
| **Боты, инструменты** | `Orpheus.Bots`, `orpheus-save`, View | C++ на тех же библиотеках | приёмки ботами остаются |
| **Клиент** | Unity 6 | **Unreal Engine 5.8** (`E:\Epic Games\UE_5.8`, VS 2022 — уже стоят), C++ модуль игры линкует ядро и сеть как сторонние библиотеки | 3D, свет, анимация (Control Rig, retarget), PS5 |
| **Тесты** | xUnit, анализатор ORP001–007 | **doctest/Catch2** + CTest; детерминизм — правила (никаких float в симуляции, порядок обхода) + clang-tidy/свои проверки | ~500 тестов переносятся вместе с кодом |

## Как переносить, не теряя проверенного

Главная опора — **C#-версия остаётся эталоном** до конца переезда:
1. Из C# выгружаются **эталонные векторы**: «золотые» байты всех сообщений, хэши состояния после N тактов с ботами, журналы ввода (`--record`), снимки генерации, файлы сохранений. C++ обязан давать побитово то же.
2. **Перекрёстная проверка:** C++-клиент (боты) подключается к C#-серверу и наоборот — протокол тот же. Это ловит расхождения, которые одиночные тесты не видят.
3. Порядок — снизу вверх, каждая часть со своими тестами и проверкой П:

| № | Карточка | Что | Приёмка |
|---|---|---|---|
| M-001 | каркас C++ | репозиторий `cpp/` (CMake, C++20, MSVC + clang), doctest, CI `tools\ci_cpp.cmd` ≤ 60 с, правила детерминизма, выгрузка эталонных векторов из C# | CI зелёный, векторы в репозитории |
| M-002 | ядро: геометрия, ГСЧ, тор, чанки, мир | порт `Core/Geometry`, `Rng`, `World`, генератор-заглушка | снимок генерации побитово = C# |
| M-003 | ядро: движение, уворот, сим, путь, правки | `Mover`, `Dodge`, `Simulation`, `Pathing`, `EditRules` | хэш состояния и журнал ввода = C# |
| M-004 | сохранения | формат 2, атомарная запись, восстановление, обрывы | файл C# грузится в C++ и обратно; 1000 обрывов |
| M-005 | сеть: протокол и транспорт | кодек, ENet, имитатор связи | «золотые» байты = C#; C++-бот ↔ C#-сервер |
| M-006 | сеть: сервер | `NetServer` целиком (обзор, дельты, часы, очередь кадров, опережение, угрозы, правки, чанки, хост) | C#-боты ↔ C++-сервер; все сетевые приёмки 0.x |
| M-007 | сервер, боты, инструменты | `OrpheusServer` C++, `Orpheus.Bots` C++, View, `orpheus-save` | приёмки 0.2, 0.6, 0.7, 0.8, 0.9 на C++ |
| M-008 | клиент UE5: каркас | проект Unreal, модуль игры, ядро и сеть подключены, камера сверху (как Diablo), мир из чанков (блоки), персонаж-болванка, ввод, предсказание и интерполяция чужих | играбельно: одиночная (сервер дочерним процессом) и хост; net-smoke |
| M-009 | клиент UE5: стиль Б | мультяшный шейдер + обводка, свет и ночь, просвечивание стен и деревьев | лист сверки со стилем |
| M-010 | удаление C# | после того, как C++ проходит все приёмки — C# и Unity из репозитория убираются (остаются в истории git) | — |

Параллельно: **комната дизайна** правит `docs/` (движок, язык, 3D, камера и шкалы экрана `00` 5.1, арт `08` 5, план `08`), **поток А** — проба 3D-арта (концепт → 3D → риг → анимация) с Мака.

## Срок (грубо)

Ядро, сохранения, сеть и сервер на C++ (M-001…M-007) — около 1–1,5 недели работы агентов (в C# это заняло ~неделю, второй раз — по готовому эталону и тестам). Клиент UE5 до играбельного (M-008) — ещё ~1 неделя. Итого переезд ≈ 2–3 недели; дальше — веха 1 уже на Unreal.

## Риски

- **Побитовое совпадение C# ↔ C++** (целая арифметика, порядок обхода, переполнения) — ловят эталонные векторы и перекрёстные прогоны.
- **ENet на PS5** — переносим, но платформенный транспорт может понадобиться — поэтому интерфейс транспорта.
- **Агенты и Unreal**: сборка UE долгая, редактор тяжёлый; обвязка `tools/ue_exec.py` из SpaceLions переносится. Один процесс редактора на копию.
- **Окна брандмауэра** — сервер по умолчанию на петле, как сейчас.
