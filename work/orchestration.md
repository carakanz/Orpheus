# Процесс работы: оркестратор → разработчики → валидатор (слово Автора 20.11.2026)

Записано по указанию Автора 20.11.2026. Действует до нового слова Автора.
Автор приходит ~через 24 часа, проверяет и отдаёт на доработку.

## Роли

1. **Оркестратор (основной тред)** — управляет, не заменяет:
   - держит очередь (`work/next.md`, `work/PLAN.md`), берёт **3 задачи одновременно**;
   - для каждой готовит карточку, контекст и рабочую копию (`.claude/worktrees/<копия>`, ветка `task/…`);
   - запускает агентов-разработчиков и валидатора, ставит им чек-лист и границы (что трогать нельзя);
   - **читает результат приёмки сам** (диск, тесты, снимки) и решает: «слить» / «на доработку» / «ждать Автора»;
   - слияние в `main`, push, журналы (`work/status.md`, `work/next.md`) — на оркестраторе.

2. **Агент-разработчик** — делает фичу в своей копии по карточке: код + тесты + снимки,
   коммиты в `task/…`, отчёт с проверяемыми фактами (файлы, строки, хэши коммитов, вывод тестов).

3. **Агент-валидатор (`reviewer`, чистый контекст)** — приёмка фичи:
   - читает карточку и дифф, гоняет CI/тесты по фильтру, сборку с гейтами;
   - **проводит приёмку на скрытом рабочем столе** (`tools\run_hidden.ps1`, `tools\shots.ps1`) —
     живой прогон сценария карточки, снимки, смотрит каждый кадр;
   - мутации (сломать — прогон краснеет);
   - пишет в конец карточки раздел `## Проверка (П)` с итогом: **принято / на доработку** + список замечаний.

## Правила

- **Три задачи параллельно.** Как только одна закрыта (слита или ждёт Автора) — берётся следующая из `work/next.md`.
- **Доклад агента — не доказательство.** Оркестратор проверяет на диске: коммиты (`git log`), файлы,
  вывод тестов (`build/logs/…`), смотрит снимки глазами. История: 4 фабрикации отчётов разработчиков —
  верить только артефактам.
- **Без «принято (П)» — не сливать** (AGENTS.md п. 3). Гейты слияния не ослаблять:
  `build_client.ps1 -Backend Mono -Smoke -HostSmoke` код 0; тяжёлый `-All` — раз в карточку,
  только если правилось ядро/сеть/сохранение; зелёное мерить `Failed: 0`, допустимы только падения
  тестов из `work/flaky.md`, прошедших поодиночке.
- **Доработка:** замечания валидатора → карточка + задачи разработчику в той же копии; повторный
  валидатор — после исправлений. Два круга без прогресса — остановиться и записать в «Ждёт Автора».
- Всё остальное — без изменений: скрытый стол для любых запусков графики/дочерних процессов,
  `git commit -F` / `merge --no-ff -F` (UTF-8 без BOM), push после каждого шага, `--public` никогда,
  Unity Hub запущен, ≥5 ГБ на C: перед сборкой, журналы коротко (AGENTS.md).
- Субагенты (`reviewer`, разработчики) — на основной модели этого ПК, можно несколько параллельно (18.11).
- Новый тяжёлый код (ядро, протокол, сохранения) — в основном треде; рутина — субагентам (AGENTS.md п. 7).

## Конец суточного цикла (приход Автора)

Оркестратор к приходу Автора держит готовым отчёт:
- что слито в `main` (хэши, числа, ссылки на карточки);
- что на доработке (замечания П, статус);
- что ждёт Автора (приёмки Автора, решения) — в `work/next.md` раздел «Ждёт Автора».
